# 저자 작성 인사이트 적용 지도

이 지도는 기존 PSST 작성법과 심사·사례 노하우를 **작성 단계에서** 적용하기 위한 참조다. 프로젝트 메모는 해당 팀의 사실·가설을 채우는 입력이고, 여기 연결된 자료는 그 내용을 어떻게 구성하고 검증할지 정하는 기준이다. 사례의 수치·경력·협력 실적을 현재 프로젝트의 사실로 옮기지 않는다.

## 작성 전에 읽는 순서

1. 실행할 모드의 `SKILL.md`와 [공통 규칙](common-rules.md)을 읽는다. 라우터를 거치지 않은 직접 호출도 같다.
2. 아래 표에서 **현재 모드 행**을 찾아 지정한 원문 절을 읽고 적용한다. 이번 작업에서 이미 읽은 현재 판본은 재사용할 수 있다. 다른 모드의 원문 전체를 무조건 읽거나 모든 스킬을 연쇄 호출할 필요는 없다.
3. 공식 양식·평가표에 맞춰 배치하고, P(작성 패턴)에 현재 분야·섹션 항목이 있으면 그 구조를 참고하되, 해당 행의 확인 기준을 작성 전 설계와 작성 후 점검에 사용한다. 양식 순서와 사용자가 중요하다고 정한 문제의 우선순위·인과 관계를 함께 보존한다.

원문 약호:

- **J**: [심사위원 인사이트](../../bizplan-review/references/judge-insights.md). J의 절을 읽을 때 첫머리의 **[확인]·[의견]·[추론] 구분**도 함께 읽는다. 사용자 노하우·의견·추론을 공식 평가 기준으로 말하지 않는다. 적용 사업·연도와 미확인 범위를 유지한다.
- **C**: [실전 사례 체크리스트](../../bizplan-review/references/case-insights.md). 첫머리의 목적·근거·사용법을 함께 읽는다. 사례에서 일반화한 작성 기준이며, 특정 팀의 수치나 사례 예문은 현재 팀의 증빙이 아니다.
- **P**: [수상작·합격 사례 작성 패턴](award-patterns.md). 분야·사업·섹션 색인에서 현재 아이템과 맞는 항목만 읽는다. 항목이 없으면 건너뛴다. 패턴은 구조·문장 공식이며 사례의 수치·팀 이력을 현재 팀의 사실로 옮기지 않는다.
- 기본 PSST 출력 형식은 각 모드 `SKILL.md`에 들어 있다. 저자 원문은 [PSST 프롬프트 마스터](https://github.com/jhsoo0211/bussiness-planner-skills/blob/182e45a113ae4945cf3b5cd4eae61dfab3993dde/docs/psst.md)에 남아 있다. 이 외부 링크는 원문 추적용이며 실행 때 웹 접속을 요구하지 않는다.

## 해석을 바꾸지 않기 위한 조건

아래 조건은 현재 모드에서 해당 주제를 다룰 때 적용한다.

- **시장 규모감:** J §4의 SOM 200억 권장선은 예창패 등 일반 트랙에 관한 사용자 노하우이며 공식 통과선이 아니다. U300은 산출 논리 타당성을 우선한다. 목표 숫자에 맞추려고 시장 범위·기간·점유율을 근거 없이 늘리지 않는다. 시장 정의를 조정하면 변경 근거를 밝힌다.
- **시장진입과 비전:** 채널·접촉·견적·예산·기대성과가 있는 실행계획을 우선한다. 자료가 없으면 확보할 행동과 시점을 제시한다. U300의 기본적인 홍보 계획은 곧바로 감점 사실로 단정하지 않고 보강 방향을 제시한다. 그 뒤 비전을 연결한다(J §4).
- **협력 단계:** 인터뷰 완료 / 협력 협의 진행 / MOU 협의 중 / MOU 체결 / 공동 수행 실적은 서로 다른 상태다. 사실 범위 안에서 명확하고 격식 있게 쓰되, 단순 미팅을 MOU 체결이나 확인되지 않은 예정 날짜로 바꾸지 않는다(J §4; C 팀 구성).
- **핵심 위험과 역량:** 직함·학력 나열로 끝내지 않는다. 실제 과업·리스크에 담당자와 검증 경험을 연결하고, 경험·인력이 없으면 필요한 역량과 확보 계획으로 쓴다(J §4; C 팀 구성).
- **문제와 해결 범위:** 문제 근거 없는 기능은 근거를 확인하거나 부가 편익으로 구분한다. 한 문제와 여러 기능, 여러 문제와 한 기능의 연결도 근거와 범위가 설명되면 허용한다. 사용자가 핵심이라 지정한 문제는 조용히 지우지 않는다. 해결책이 없으면 **미해결 / 추가 검증 필요 / 현재 범위 밖**을 명시하고 필요한 검증·후속 과제로 남긴다. 일부만 해결한다면 한계를 쓰고 효과를 과장하지 않는다. 기존 원문의 1:1·비중 조정 표현을 문제 삭제나 사용자 동의 없는 방향·우선순위 변경으로 적용하지 않는다(C 문제인식; 공통 규칙의 사용자 요구 보존).
- **수치·상태:** 예창패 예시 예산·기간을 실제 공고 값으로 바꾸고, 출원·등록·성능 검증·자금 확보의 상태를 입력 증빙대로 구분한다. 미제공 수치는 산식·필요 변수·확보 계획으로 남긴다. 사례의 예문을 현재 프로젝트의 실적으로 채우지 않는다(공통 규칙; C 미확정 클레임·급경사 재무).

## 출력 직전 확인

현재 모드 행의 기준을 실제 본문에 적용했는지 점검한다. 참조를 읽었다는 사실만으로 적용 완료라고 판단하지 않는다. 근거가 없어서 적용하지 못한 부분은 사용자가 확인할 항목과 구체적 보강 계획으로 남긴다. 이 지도의 약호·파일 경로·내부 점검표를 사업계획서 본문에 넣을 필요는 없다. 사용자는 완성된 서술과 필요한 확인 사항을 받는다.
