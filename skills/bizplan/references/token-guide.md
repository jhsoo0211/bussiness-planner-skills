# 토큰 소모 가늠표 · 모델 추천

> 이 표의 등급은 **측정 전의 대략적인 가늠**이며 모델 간 벤치마크가 아니다. 스킬 자체는 토큰 사용량을 셀 수 없다. Codex·Claude Code 등 현재 호스트가 제공하는 사용량·한도 표시를 참고하고, 값이 없으면 알 수 없음으로 남긴다. 특정 제품 전용 명령을 다른 제품에서 쓸 수 있다고 안내하지 않는다.

## 모드별 대략 소모 가늠표

상대 등급만 본다(적음 < 중간 < 많음). 실제 값은 대화 길이·조사량에 따라 크게 달라진다.

| 작업 | 상대 소모 | 무엇이 토큰을 먹나 | 절약 팁 |
|------|-----------|--------------------|---------|
| 빠른 초안 (`bizplan-quick`) | 적음~중간 | 한 번의 전체 생성 | 각 파트 핵심 기준을 적용하되 분량을 축약. 미확보 수치는 산정·검증 계획으로 남김 |
| 큰틀 보기 (`bizplan-outline`) | 적음 | 목차·요약·증빙 슬롯 표 한 번 | 양식·배점표를 먼저 받아 재작업을 줄인다. 이후 섹션 작성의 왕복이 줄어든다 |
| 특정 섹션 1개 (`bizplan-problem` 등) | 중간 | 인터뷰 왕복 + 생성 | 질문을 한 번에 묶어 왕복을 줄인다 |
| 꼼꼼 전체 파이프라인 | 많음 | **긴 context 누적** + 웹 실조사 | 파트별로 대화를 끊는다 / 조사는 뒤로 미룬다 |
| 시장 조사 (`bizplan-research`) | 중간~많음 | 웹 검색·다수 출처 대조 | 핵심 수치 2~3개만 우선 조사 |
| 심사위원 검토 (`bizplan-review`) | 중간~많음 | 출처 검증 웹 조사 | 검증은 제출 직전 한 번만 |
| 시각자료 (`bizplan-visual`) | 중간 | matplotlib 코드 재실행 반복 | 도식 안을 먼저 확정한 뒤 한 번에 생성 |
| 벤치마킹 분석 (`bizplan-analyze`) | 많음 | 다수 문서(PDF) 통독 + 교차 비교 | 문서를 2~3건으로 추리고 핵심 섹션 위주로 발췌 분석 |
| 슬라이드 제작 (`bizplan-slides`) | 중간~많음 | 템플릿 분석·스펙 작성(PPTX) 또는 HTML 생성 + 렌더 검수 반복 | 구성안(bizplan-pitch)과 레이아웃 매핑표를 먼저 확정한다. 렌더 확인은 모아보기 한 장으로 |

## 단계별 모델 선택 기준

모델은 현재 제품에서 실제 선택 가능한 목록을 기준으로 사용자가 고른다. 모델명·가격·구독 한도를 고정해 가정하지 않는다. 아래는 비교 실험을 위한 선택 기준이며 특정 모델의 품질·속도 우위를 보장하지 않는다.

| 단계·작업 | 비교할 특성 | 확인할 결과 |
|-----------|-----------|------|
| 문제 프레이밍(`bizplan-problem`), 성장전략(`bizplan-growth`), 심사 검토(`bizplan-review`), 발표 Q&A(`bizplan-pitch`) | 복잡한 추론·검토에 적합한 설정 | 논리 정합성, 근거 없는 주장 탐지, 수정안의 실용성 |
| 시장 조사 정리(`bizplan-research`), 실현가능성·일정(`bizplan-solution`), 팀(`bizplan-team`), 개요(`bizplan-summary`) | 구조화 품질과 지연 시간의 균형 | 누락·오독·계산 오류, 양식 준수 |
| 단순 리라이트, 표 형식 정리, 오탈자·문장 다듬기 | 짧은 응답 지연과 원문 보존 | 의미 변형, 사실 추가, 형식 오류 |

- 요금제 이름만으로 모델을 낮추거나 결과를 축약하지 않는다. 사용자가 절약을 요청하거나 호스트가 한도 도달을 알릴 때만 작업 방식 변경을 제안한다.
- 서로 다른 제공자의 토큰 수를 같은 금액으로 해석하지 않는다. 측정한 지연 시간·사용량과 공식 가격 정보가 있을 때만 조건을 밝히고 비교한다.
- 실제 작성 성능은 같은 입력·도구·스킬 버전으로 평가한다. 설치 smoke·예시 산출물은 품질 비교의 근거가 아니다.
