# 섹션 설계도 — 작성 블록 · 양식 매핑

사업계획서를 **블록**(증명할 것 하나의 단위)으로 쓰고, 공고 양식 목차에 배치하는 기준이다. 모든 작성 모드가 이 문서를 따른다(저자 인사이트 지도의 약호 **B**).

## 0. 쓰는 법

1. 블록 B1~B14로 쓴다.
2. 공고 양식이 있으면 **4절 양식 매핑**으로 블록을 목차 칸에 배치한다. 없으면 4-1의 기본 목차를 쓴다.
3. 모든 블록은 **1절 공통 문법**을 따른다. 번호가 붙은 절(1-1, 2-2 등)마다 **3절 시각자료 슬롯**을 하나 이상 둔다. `○` 헤드라인마다 두는 것이 아니다.
4. 숫자는 **숫자 등록부**(1-6)에 먼저 적고, 그 값만 쓴다.
5. 온라인 문항형 양식(글자 수 제한 입력창)은 **5절**을 따른다.

## 1. 공통 블록 문법

### 1-1. 헤드라인 공식

```
○ [태그] 결론 문장 — 주어는 고객·팀·제품, 숫자 1개 이상 권장
```

- 소제목은 라벨("시장 배경")이 아니라 **주장**("1차 고객은 ○○ 중 ○○곳이다")으로 쓴다.
- 헤드라인만 이어 읽어도 문제 → 해결 → 성장 → 팀이 이해되어야 한다.
- 숫자는 권장이다. 아직 없으면 결론만 쓰거나 ○○ 자리로 둔다(지어내지 않는다).
- 헤드라인 줄은 `○`(문항형은 `◆`)로 시작한다. 불릿(`- ○`)·굵게(`**○ …**`)·제목 줄(`#### ○ …`)도 같은 헤드라인으로 센다.

**태그 어휘** — 양식에 정해진 용어가 있으면 그것을 쓰고, 없으면 아래를 쓴다.

| 블록 | 태그 |
|------|------|
| B2 개요 | `[한 줄 소개]` `[명칭]` `[범주]` `[아이템 개요]` `[문제 인식]` `[실현 가능성]` `[성장 전략]` `[팀 구성]` |
| B3 배경 | `[내부 배경]` `[외부 배경]` `[왜 지금]` |
| B4 문제 | `[필요성 1]` `[필요성 2]` … |
| B5 시장·고객 | `[진입시장]` `[1차 고객]` `[고객 특성]` |
| B6 준비 정도 | `[보유역량]` `[진행역량]` `[미확보]` |
| B7 구체화 | `[솔루션 1]` `[솔루션 2]` … |
| B8 차별 | `[차별점 1]` … `[우위 유지]` |
| B9 사업비 | `[집행 계획]` `[1단계]` `[2단계]` `[자기부담]` |
| B10 BM | `[비즈니스 모델]` `[가격 근거]` |
| B11 진입 | `[진입 경로]` `[퍼널]` |
| B12 3지표 | `[협약 기간 내]` `[협약 기간 이후]` |
| B13 로드맵 | `[로드맵]` `[일정]` |
| B14 팀 | `[대표자]` `[R&R]` `[보완 계획]` `[협력]` |

### 1-2. 블록 순서

```
○ [태그] 결론 헤드라인
[시각자료] 제목 = 결론 수치 / 아래 한 줄 = 범위 · 출처 · 시점 · 표본
- 근거 2~4줄 — 한 줄에 사실 하나, 핵심구 **굵게**, 결정 문장 하나만 [밑줄]{.underline}
(출처: 기관, 연도) · (*별첨 ○) · (확인 경로: ○○)
```

- 별첨·쪽 교차 참조("(*견적서 별첨)", "(*○쪽 참조)")는 실제로 첨부하는 자료에만 단다.

### 1-3. 문장 규칙

| 규칙 | 고치기 전 | 고친 뒤 |
|------|-----------|---------|
| 형용사를 숫자로 | 혁신적 기술로 압도적 효율 | ○○ 시간을 ○○분에서 ○○분으로 |
| 대상을 좁게 | 모든 소상공인에게 | ○○ 지역 1인 운영 ○○ ○○곳 |
| 예정을 상태로 | 개발을 완료할 예정 | 화면 설계 ○매 완료, ○○만 남음 |
| 한 문장 2줄 이내 | ~하고 ~하며 ~함으로써 ~하는 | 두 문장으로 자른다 |
| 셋씩 나열 금지 | 빠르고 정확하며 효율적인 | 가장 중요한 하나 + 근거 |
| 소제목으로 묶기 | 긴 문단 연속 | 무엇을 / 어디까지 / 어떻게 팔지 / 누구와 |

- 한 문단(근거 묶음)에 숫자는 2~3개까지만 쓴다.
- 확인 방법: 소리 내어 읽어 숨이 차면 자른다. 설명하지 못하는 문장은 지운다.

### 1-4. 문체 — 양식별 자동

| 양식 유형 | 헤드라인 | 근거 | 제출본 |
|-----------|----------|------|--------|
| **문서형**(HWP·DOCX 양식: 예창패·초창패·U300+·청창사 등) | `○ [태그] 결론 문장` | 개조식(명사형 ~함·~임, 체언) | `□ → ○ → - → ·` 계층(`--gov-bullets`) |
| **온라인 문항형**(입력창·글자 수 제한) | `◆ 소제목` | 짧은 서술 문단(한 문장 2줄 이내, 문단 사이 빈 줄) | 입력창 서식(굵게·목록)만, 표는 이미지로 |
| **발표** | 헤드라인 문장 | 키워드 3±1줄 | — |
| **완성 문서**(`bizplan-document`) | `#### ○ 주제구`(밑줄) + `##### 소주제` | 경어체 서술 문단 2~4문장(표·개요 칸만 개조식) | 완성 문서 서식(`--style form`, `bizplan-document/references/document-format.md`) |

- 온라인 문항형은 같은 어미·같은 길이의 문단을 반복하지 않는다. 숫자 없는 균일한 문단과 같은 종결어미의 연속은 기계가 쓴 글처럼 읽힌다.
- 문서형은 `.md` 초안에서도 근거 줄을 명사형 개조식으로 쓴다(마크다운 불릿 `-`). 헤드라인은 `~다` 결론 문장으로 둔다. 변환할 때 불릿이 `□ ○ - ·` 계층으로 바뀐다.
- 사용자가 문체를 지정하면 그것을 따른다.

### 1-5. 번호 실

- 문제 `[필요성 1·2]` → 해결 `[솔루션 1·2]` → 차별 `[차별점 1·2]` → 화면·실물 라벨 ①②를 **같은 번호**로 잇는다.
- 개요와 발표도 같은 번호를 쓴다.
- 한 문제에 기능이 여럿이거나 여러 문제에 기능 하나여도 된다. 번호로 대응을 밝힌다.
- 대응이 없으면 `미해결 / 추가 검증 필요 / 현재 범위 밖`으로 적는다(공통 규칙의 문제-솔루션 대응 원칙).

### 1-6. 숫자 등록부 (쓰기 전에 만든다)

| 값 | 의미 | 산식 · 출처 · 시점 | 근거 수준 | 들어갈 블록 |
|----|------|---------------------|-----------|-------------|
| ○○명 | 인터뷰 표본 | 자체 조사, 2026.○ | 관찰 | B3·B4·B14 |
| 월 ○○건 | 고객당 문제 빈도 | 인터뷰 중앙값 | 관찰 | B4 |
| 월 ○○만 원 | 손실 환산 | 단가 × 빈도 | 산출 | B4·B10 |
| ○○곳 | 1차 고객 모집단 | 공공 데이터, 2026.○ | 확인 | B5·B10·B11 |
| ○○원 | 단가 | 지불 의향 중앙값 / 경쟁가 | 관찰·확인 | B10·B12 |

- 6~10개를 `브리프.md`의 '숫자 등록부' 절에 둔다. 개요·본문·그림·발표·작성 가이드는 이 값만 쓴다.
- **등록 대상**: 두 곳 이상에 반복되거나 헤드라인·개요·3지표·발표에 쓰는 숫자.
- **등록하지 않는 숫자**(출처는 조사노트 출처 표에 둔다):
  - 시계열 그림의 중간값
  - 공고 기본값(지원 한도·협약 기간 — 공고문이 출처)
  - 조사 계획의 표본 수(실제로 조사한 뒤에 등록한다)
  - 등록부 값에서 계산한 비율(그 산식을 등록부 '산식' 칸에 적는다)
- 10개를 넘으면 반복이 적은 값부터 출처 표로 내린다.
- 값이 바뀌면 등록부를 먼저 고치고, 쓰인 곳을 모두 고친다.
- 제출 전에 본문·발표를 등록부와 대조한다(`bizplan-slides/scripts/deck_check.py --against 브리프.md`).

### 1-7. 근거 수준 · 확보 단계 · 판정

**근거 수준 라벨**(수치마다 단다)
- `확인`: 공공·제3자 문서
- `산출`: 확인된 값으로 계산
- `관찰`: 자체 인터뷰·설문·실측
- `가정`: 근거 없음 — 확보 계획 필수

**확보 단계**

| 단계 | 기간 | 근거 | 들어갈 곳 |
|------|------|------|-----------|
| 0 | 하루 | 공개 통계·행정 자료, 기사, 커뮤니티 글·리뷰, 경쟁 공개 요금표, 본인 경험 | 배경, 문제 규모, 비교표 |
| 1 | 2~3일 | 인터뷰 5~10명, 현장 관찰, 온라인 설문 30명 | 문제 확산, 지불 의향 |
| 2 | 1~2주 | 목업 반응, 한 장 소개문 사전 신청, 사전 예약 | 확인 계획, 첫 고객 |
| 3 | 4주 이상 | 시범 운영, 적용 전후 수치, 재사용 의사 | 검증 결과 |

- 마감까지 닿는 단계까지만 수행하고 나머지는 계획으로 쓴다. 0단계만으로도 제출할 수 있다.

**판정**(조사·검토에서 수치마다)
- `그대로 사용`
- `단서와 함께`: 범위·연도·정의를 붙여 쓴다
- `재조사`

### 1-8. 실적이 없을 때 · 미확보 공개

- **확인 계획 3요소**: 언제까지 · 누구를 · 무엇을.
  - 예: "○주 안에 ○○ ○곳을 방문해 도입 의향과 지불 가능 금액 두 가지를 확인한다."
- **미확보 선제 공개**: "확보하지 못한 것도 있다: ○○. 지금 상태로는 ○○ 이상 늘릴 수 없다."
- 없다고 쓰는 것은 감점이 아니다. 감점은 근거 없이 단정한 문장에서 나온다.

### 1-9. 보수 추정 · 검산

- 의향률·전환율·재구매율은 **조사값의 절반**을 쓰고 이유를 한 줄 적는다.
- 계산한 단가가 지불 의향 중앙값을 넘으면 첫해 상한을 둔다.
- 산식은 곱셈을 그대로 보인다: `대상 수 × 전환율 × 단가 = 금액`.
- 합계가 나오는 표 아래에 **검산 상자** 한 줄을 둔다("3년 차 ○억 원 = …").
- 넘기기 전에 `check_tables.py`로 검산한다(공통 규칙 '숫자 검산').

## 2. 블록별 설계도

### B1. 한 줄 소개 · 아이템명
- **공식 1**: `[타깃 고객]의 [측정 가능한 문제]를 [해결 방식]으로 줄이는 [결과물]`
- **공식 2**(콜론형): `[…줄이는 결과물] [이름] : [작동 방식 한 줄]`
- **아이템명 공식**: `[기술]이 적용된, [혜택]을 제공하는, [제품/서비스]`
- **검증**: 제3자에게 한 줄만 보여 주고 대상·문제를 되말하게 한다. 맞히지 못하면 다시 쓴다.
- **금지**: "혁신적 AI 기반 통합 플랫폼"류, 세 요소 중 하나라도 빠짐, 브랜드명만 있음, 느낌표·질문형.
- 본문을 다 쓴 뒤 축약해서 쓴다.

### B2. 개요(요약) — 본문의 축소판
- 칸마다 `○ 헤드라인 + 사실 1~2줄`을 쓴다. 숫자는 등록부 값만 쓴다.
- 칸 구성은 양식을 따른다. 없으면 명칭 · 범주 · 아이템 개요 · 문제 · 실현 · 성장 · 팀 · 이미지.
- 분량은 양식 지시를 따르고, 지시가 없으면 1~2쪽이다.
- 이미지 2장: 실물·화면 1 + 구조(BM·흐름) 1.
- 번호 실(①②)을 여기서도 보인다.
- 마지막에 쓴다. 본문에 없는 사실은 넣지 않는다.

### B3. 배경 — 내부 · 외부 · 왜 지금
1. `[내부 배경]` 장면: 언제·어디서·무엇을 보고 알았는가(대표·팀의 직접 경험, 숫자 1개). 현장 사진 1장 + 캡션.
2. 확인 행동: 그 뒤 실제로 한 일(인터뷰 인원·기간·장소).
3. 확산 확인: 개인의 불편이 아니라는 근거(표본 중 같은 경험 비율).
4. `[외부 배경]` 공적 통계 1~2개(출처·연도)로 구조적 압력을 보인다. 문제는 크게, 해법은 좁게.
5. `[왜 지금]` 제도 변화 / 수요 변화 / 기술 가격 하락 중 **하나**만.
- **금지**: "평소 불편함을 느껴 왔다"로 시작하기, 일반 사회 문제를 그대로 옮기기, B4와 다른 대상, 감상문.

### B4. 문제 정의 — 필요성 n
- **공식**: `[누구]가 [어떤 상황]에서 [어떤 문제]로 [얼마나 자주/심각하게] 겪는다`
- 근거 줄
  - 빈도·심각도 수치
  - 손실 환산(시간·금액 — "돈을 내서라도 풀고 싶은가")
  - **현재 대처행동**과 그 한계(B8의 대체재로 이어진다)
  - 출처·조사 기간
- 문제는 2~3개, 우선순위대로 쓴다. 사용자가 정한 핵심 문제는 바꾸지 않는다.
- 양면 시장이면 문제를 쪽마다 따로 쓰고, 누가 돈을 내는지는 B10에서 정한다.
- 시각자료: 커뮤니티·리뷰 캡처(개인정보 가림), 조사 결과 차트(표본·기간 표기), 문제 발생 흐름도.
- 끝에 해결 요약 한 줄: "① ○○과 ② ○○를 푸는 [서비스명]".

### B5. 목표시장 · 고객
- **TAM → SAM → SOM 산식**: 층위마다 산식과 출처를 단다.
  - **결제자 기준**으로 센다. 사용자 ≠ 결제자면 둘 다 표기한다.
  - TAM은 하향식, SAM은 상향식(결제자 모집단 × 연 지출, 하향식 값과 대조), SOM은 상향식(고객 수 × 단가)으로 계산한다(조사 스킬 2절).
- `[1차 고객]` **고객 수까지** 좁힌다: `모집단 × 발생률 × 도입 의향(× ½) = 초기 고객 ○○곳`. 이름 붙은 작은 집단(지역·업종·규모)으로 쓴다.
- `[고객 특성]` 페르소나 카드
  - 한 줄 정의와 해시태그 4개(연령·신분·행동 빈도·상황)
  - 사용 장면 1~2문장
  - 불편 장면 인용 3개(심리 → 기회비용 → 금전 순서). 따옴표는 실제 발언에만 쓴다. 인터뷰 전이면 따옴표 없이 '(가설)'을 붙인다.
  - 검증 n/N(실제 인터뷰가 없으면 '가상'으로 표시)
- 세분화 4기준: 측정 · 접근 · 구매력 · 니즈 동질성.
- 시각자료: 동심원 + 층별 산식(`tam` — 1차 고객 수를 안쪽 층으로) + 아래 한 줄 메시지, 페르소나 카드. 진입 퍼널(B11)과 이름을 섞지 않는다.

### B6. 준비 정도 — 보유 · 진행 · 미확보
- `[보유역량]` 경험 횟수·기간·인원·자산(연락처·데이터·장비).
- `[진행역량]` 산출물별 상태 **완료 / 진행 / 예정**(날짜). 견적·LOI는 "(*별첨)".
- `[미확보]` 되는 것 / 안 되는 것 / 확보 못한 것을 한 줄씩.
- 시각자료: **실물 증빙 격자**. 2~4열 사진에 아래 캡션 칸(무엇·언제)을 둔다. 대상은 시제품, 화면, 시설, 등록증·자격, 활동 장면.

### B7. 구체화 — 솔루션 n
- `[솔루션 n]` = 문제 n ↔ 기능 ↔ **고객 편익**(수치·조건, 예: "반경 ○km 안에서 ○분 안에").
- 화면·실물 흐름은 단계 4개 이하, 단계마다 시각·상태, 번호 라벨 ①②③.
  - 동작하지 않는 기능은 '계획'으로 표기하고 구현된 것처럼 그리지 않는다.
- 기술 구조도 1장, 핵심 기술 3개(구현 난이도·확보 방안).
- 기술 보호: 지재권 상태(출원·등록·검토), 보안 서약 등 실제로 한 것.
- 리스크 2개, 각각 대응 한 줄(기술·규제·인허가). 규제 판단이 걸리면 두 갈래로 대응한다("먼저 확정되는 쪽으로 착수").

### B8. 차별 · 경쟁
- **비교표 규칙**
  - 실명 3곳 이상 + **대체재**(고객의 현재 대처행동).
  - 비교 축 3개(고객 구매 기준).
  - **자사가 불리한 축 1개 이상**.
  - **확인 경로 열**(공식 안내·요금표 URL·확인 시점). 확인 안 된 칸은 "공개 안내 없음".
  - 자사 열만 강조색. 정성 항목은 별점, 정량 항목은 금액. 맨 아래에 단위 비용(절대 금액·비율).
- `[차별점 n]` 문장 틀: "[경쟁 X]는 [가격 조건]으로 [제공 범위]까지 → 우리는 같은 축에서 [측정값] → 차이의 원인은 [구조]."
- `[우위 유지]` 관계 · 계약 · 축적 데이터 가운데 하나 + 실제 건수. "경쟁사가 같은 기능을 붙이면 무엇이 남는가"에 답한다.
- 시각자료: 비교표 1, 포지셔닝맵(대체재 포함) 선택.
- **금지**: "경쟁자 없음", 모든 항목 자사 우위, 저가만 우위, 익명 A사·B사.

### B9. 사업비 집행
- 비목 · 산출 근거(단가 × 수량 · 견적처) · 금액 · 비율. 합계는 상한과 정확히 일치한다.
- 공고 비목 기준을 따르고, 1·2단계를 구분한다(`bizplan-solution` B절).

### B10. BM · 수익
- 한 문장 공식: `[초기 N명/곳]에게 [상품]을 [가격/주기]에 [과금 방식]으로 판다`
- **BM 구조도**: 주체(결제자·사용자·파트너)와 그 사이에 **주고받는 것**을 화살표 이름으로 쓴다 — 우리가 주는 것(서비스·SW·데이터·장비)과 받는 것(사용료·구독료·수수료·데이터). 돈은 실선, 서비스는 점선. 금액은 그림에 쓰지 않고 아래 매출 산식에 둔다.
- **매출 산식**: `대상 수 × 전환율(½ 적용) × 단가 = 금액`. 상품군이 둘 이상이면 행을 나눈다.
- **단가 근거**: 지불 의향 중앙값 / 경쟁가 / 절감분 대비 %("절감액의 ○○% 수준").
- 결제자를 명시한다: 누가 왜 내는가, 그 과금 방식을 고른 이유.
- 수익원 표: 수익원 · 과금 · 단가 · 3년 차 비중. 계획 없는 칸은 줄표.
- 재화형은 개당 원가 구성(원물·가공·포장·부자재 = 원가율)과 월 최대 생산량을 둔다.
- **금지**: "사용자 먼저 모으고 수익화는 나중", 광고·수수료를 근거 없이 나열, 시장 규모만 있고 자사 몫 없음.

### B11. 시장 진입
- `[퍼널]` 모집단 → 접촉 → 설명 → 사전 신청 → 유료. 단계마다 인원·구간 전환율·근거 라벨.
- 채널표: 접촉 대상 · 접촉 방식 · 목표 · 단위 비용 · 근거.
  - 채널명만 나열하지 않는다. 범용 홍보(홈페이지·SNS)는 접촉·견적·예산이 있을 때만 쓴다.
- **접촉 완료 인원**을 따로 강조한다(실행력의 지표). 1인 실행량 상한(주 ○곳)을 현실적으로 둔다.
- 세부 타겟별 유입 전략 표(세그먼트 → 전략)는 선택이다.
- 채널별 기대 매출은 산식과 함께 쓴다.

### B12. 매출 · 투자 · 고용 (3지표)
- `[협약 기간 내]` 세 줄을 쓴다.
  - **매출**: 금액 + 산식 + 근거(등록부).
  - **투자**: LOI 금액·투자자 유형·조건(마일스톤·밸류·방식). 없으면 "○곳 미팅 진행 중(○월)" 같은 실제 행동.
  - **고용**: 포지션 × 시기 × 인원("○월 개발자 ○명").
- `[협약 기간 이후]` 3년 표: 고객 수 · 단가 · 매출 · 비용 · 영업이익 · 고용. 아래에 검산 상자.
- 흑자 전환 시점과 조건 2개(예: 전환율 ○%, 유지율 ○%).
- 수치는 팀 사실·근거로만 쓴다. 권장선(지원금 이상 매출 등)은 작성 가이드에 '참고 의견'으로만 둔다.

### B13. 로드맵 · 일정
- 칸마다 `과업 → 산출물 → KPI → 고객 → 매출`이 이어진다.
  - 약한 예: "Q1 앱 개발 완료"
  - 강한 예: "Q2 유료 요금제 출시 → 전환율 ○% → ○곳 → 월 ○만 원"
- 행은 성과 축(제품·고객 검증·판매·제휴·마케팅·조직·자금) 7개 이내다. 1년 차는 분기, 2년 차부터는 연 단위이고, 마지막 행은 KPI다.
- 손익 변곡점과 같은 칸에 ★를 단다. 아래에 인과 문장 한 줄: "[시점]에 [과업]을 하기 때문에 [KPI]가 나고 매출이 [a]에서 [b]가 된다."
- 협약 기간 일정표: 월차 · 활동 · 산출물 · 예산.
- 재화형은 인증과 생산 능력 행이 필수다. 생산 능력을 넘는 판매 목표는 쓰지 않는다.

### B14. 팀
- `[대표자]` 당사자성(이 문제를 겪었거나 처리해 본 사람) + 문제와 연결된 경력·전공 + 준비 행동(날짜순).
  - "적임자인 이유 한 문장"으로 마무리한다. 스펙 나열은 하지 않는다.
- `[R&R]` 표: 분야 · 담당 · 보유 역량 · **책임 범위(문장)** · 상태(**확보 / 예정 / 협의 중** 세 값).
  - 예정 칸에는 합류 시점과 그때까지 대신할 사람을 적는다.
- `[보완 계획]` 표: 현재 역량 · 공백 · 보완(채용·자문·제휴) · 시점(분기) · 빈도 · 예산 · 검증 주체.
- 협업 구조 한 줄(주간 리듬·도구).
- `[협력]` 표: 기관 · 보유 역량 · 협력 내용 · **협력 시기**(조건부 가능: "매출 ○ 달성 후") · 단계(접촉 < 협의 < LOI < MOU < 공동 실적).
- 시설·장비·공간 확보 현황(사진 격자 가능).
- 블라인드: 실명·학교·직장명은 ○○로 쓴다.

### 3-2. 이미지 예산
- **문서형 10쪽 내외**: 시각자료 12~16개(번호 절마다 1개 이상). 배점이 큰 문제(B4)·차별(B8)·BM(B10)에 몰아 준다.
- **무엇을 세나**: 그림(차트·도식·사진·화면)을 센다. 표는 예산에 세지 않는다. 다만 3-1에서 그 절의 증명 형식으로 정한 표(B8 비교표, B9 비목 표, B12 3년 표, B14 R&R 표)는 그 절의 슬롯을 채운 것으로 본다. 표에 `[시각자료]` 라벨을 따로 달지 않는다.
- **온라인 문항형**: 공고의 총량(예: 전체 10장)을 배점이 큰 문항에 6장 안팎으로 배분한다.
  - 이미지마다 바로 위 문단을 뒷받침해야 한다.
  - 같은 내용을 다르게 그린 장은 빼는 편이 낫다.
- 작성 시작 때 **이미지 예산표**(블록 · 증명 대상 · 형식 · 담당 · 상태)를 브리프나 큰틀에 만든다.
- 사용자 자산이 없을 때(아이디어 단계): 스킬이 만드는 도식·표로 먼저 채운다. 사진 자리는 `[이미지: …]`로 남기고 무엇을 찍을지(대상·장소·캡션)를 요청한다.

### 3-3. 규칙
- **사진 캡션**: 촬영일 · 장소 · 대상 수. 얼굴·개인정보는 가리고 초상 동의를 확인한다.
- **차트**
  - 제목에 결론 수치("○주 시범 운영 · ○○ ○○분 → ○○분").
  - 아래 한 줄에 범위·출처·시점·표본.
  - 자사(도입 후)만 강조색, 3D·그림자 금지, 전후 지표 2개까지, 막대 위 수치, 축 왜곡 금지.
- **표**
  - 확인 경로 열, 산정 기준 열, 검산 상자, 상태 3값, 근거 라벨을 둔다.
  - 계획 없는 칸은 줄표로 둔다.
  - "이 표에 넣지 않는 것"을 정해 범위를 지킨다.
- **이미지 격자(문서)**: 마크다운 표 한 줄에 그림을 2~4개 두고, 다음 줄에 캡션을 둔다. `md_to_docx.py`가 칸 너비에 맞춰 줄인다.

## 5. 온라인 문항형 출력 형식

입력창·글자 수 제한 양식(모두의 창업 도전신청서 등)용이다. 문항 구성·분량·이미지 한도는 회차 공고로 확인한다.

**공통**
- **작성 순서는 재료 순서**다: 가장 긴 문제·차별 문항 → 배경 → 수익 → 사업화 → 역량 → 지원 요청 → 개선점 → 한 줄 소개 → 영상.
  - 한 줄 소개를 먼저 쓰면 본문이 그 문장에 묶인다.
- **분량**: 한도의 80%가 하한이다. 분량은 형용사가 아니라 숫자·출처·시점으로 채운다. 덩어리 수를 늘리지 말고, 각 덩어리에 숫자·출처·시점을 하나씩 더한다.
- **표기**: `◆ 소제목` + `① ②` 번호 + `·` 불릿, 문단 사이 빈 줄. 표·계산은 이미지로 올리고 본문은 그 이미지를 설명한다.
- **이미지**: 총량을 배점이 큰 문항(문제·차별, 수익)에 6장 안팎으로 몰아 준다. 이미지마다 넣을 위치(문항·덩어리)를 정한다.

| 문항 성격 | 덩어리(권장 분량은 한도 2,000자 기준) |
|-----------|----------------------------------------|
| 한 줄 소개 | 타깃 · 측정 가능한 문제 · 해결 동사 · 결과물 정체(B1 공식, 85~95자) |
| 아이디어 배경 | ① 장면(시점·장소·금액) ② 확인 행동(인원·기간) ③ 확산 확인(비율) ④ 지금 하는 이유 → 다음 문항 첫 문장. 900~1,300자, 현장 사진 1장 |
| 차별점과 해결할 문제(배점 핵심) | ① 해결할 문제 400~500자 ② 왜 지금 150~200자 ③ 차별점(실명 2~3·축 3) 600~700자 ④ 우위 유지 근거 250~300자 ⑤ 검증 결과 또는 확인 계획 200~300자 |
| 수익 창출 | ① 과금 구조(누가·어떻게) ② 단가 근거 ③ 목표 산정(단가 × 고객 수) ④ 손익(매출·비용·영업이익, 계산 과정) ⑤ 지속 가정(재구매·이탈, 절반 적용 이유) |
| 사업화 계획 | ① 현재 단계(확보/미확보) ② 첫 단계 계획·활동자금 비목별 근거 ③ 이후 분기별 과업·산출물·KPI ④ 첫 고객 확보(접촉 완료 수) ⑤ 장애물과 대응(규제·인력) |
| 본인 역량 | ① 문제 해결 자격 ② 준비 행동과 시점 ③ 분야별 R&R ④ 부족 역량과 보완(비용·시점) — 말미에 부족 항목 명시 |
| 멘토·지원 요청 | ① 지금의 병목 하나 ② 풀리면 달라지는 것(숫자) ③ 요청 산출물과 시점 ④ 스스로 준비할 몫 ⑤ 기관을 고른 이유. 역량 문항의 약점 중 가장 이른 것 |
| 이전 대비 개선점 | ① 이전 원안 ② 받은 지적과 확인한 사실 ③ 바꾼 것 ④ 바꾸지 않은 것과 이유 ⑤ 새로 생긴 숫자. 신규 지원자는 자기 초안 대비로 쓴다 |
| 소개 영상(30~60초) | 0~10초 문제 장면·손실 수치 / 10~30초 사용 장면 / 30~50초 전후 수치(표본·기간 자막) / 50~60초 본인 얼굴로 다음 단계. 신청서 숫자만 쓴다 |

- **문항 간 정합**: 배경 표본 수 = 문제 문항 수치, 지원 요청 = 역량 약점, 팀원 수 = R&R 확보 인원, 이미지 값 = 본문 값, 영상 숫자 = 본문 숫자.
- **선택 문항**을 비워 두면 준비 부족으로 읽힌다. 영상은 심사자가 확인해야 의견을 남길 수 있는 경우가 있으니 사실상 필수로 본다(공고 확인).
