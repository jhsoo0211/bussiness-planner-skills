# 수상작·합격 사례 작성 패턴 (분야 × 사업 × 섹션)

합격·수상 사업계획서에서 뽑은 **구조와 문장 공식**만 모은다. 작성 모드는 저자 인사이트 지도의 약호 **P**로 이 파일을 참조하고, 현재 아이템과 분야·사업·섹션이 맞는 항목만 읽는다.

## 넣는 규칙

- **원문은 저장소에 넣지 않는다.** 원문 PDF·HWP는 로컬 `자료/`(gitignore) 또는 비공개 저장소에 두고, `bizplan-analyze`로 분석해 패턴만 여기에 옮긴다. 이 저장소는 공개다.
- 사례는 `사례 A`처럼 익명으로 부르고 분야·사업·연도만 남긴다. 팀명·실명·학교·회사·고유 수치는 쓰지 않는다. 수치가 패턴의 핵심이면 "원 단위까지 공개", "구매의향서 면적으로 점유율 역산"처럼 **방식**으로 일반화한다.
- 항목마다 근거 수준을 단다: **[합격 확인]**(결과를 확인한 사례) / **[수상 확인]** / **[사용자 제공]**(결과 미확인).
- 검토 체크리스트 성격의 교훈은 `bizplan-review/references/cases/`, 시각자료·증빙 패턴은 `bizplan-visual/references/visual-guide.md`에 넣는다. 여기에는 **쓰는 법**만 둔다.
- 설치본 스킬 폴더는 고치지 않는다(공통 규칙 '참조 문서 갱신'). 저장소 원본에서 작업할 때 사용자 동의를 받아 추가한다.

## 항목 형식

```markdown
### [분야] · [사업] · [섹션] — 패턴 이름 (사례 A·B, 근거 수준)
- 구조: 이 섹션을 어떤 순서·칸으로 짰는가(소제목 흐름)
- 문장 공식: 재사용할 문장 틀(예: "[대상] [N명] 중 [N%]가 [문제]를 겪는다(출처) → 그래서 [기능]")
- 왜 통했나: 심사 관점의 이유 한 줄
- 주의: 이 패턴이 맞지 않는 경우
```
