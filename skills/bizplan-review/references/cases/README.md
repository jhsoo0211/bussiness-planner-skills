# 사례 기반 검토 교훈 — 분야별 색인

`case-insights.md`(공통 체크리스트)에 더해, 자료가 쌓이면 **분야별 파일**로 나눠 넣는다. `bizplan-review`는 이 색인을 읽고 검토 대상과 분야·사업이 맞는 파일만 연다 — 모든 사례를 매번 읽지 않게 하려는 구조다.

## 넣는 규칙

- 원문은 저장소에 넣지 않는다(로컬 `자료/` 또는 비공개 저장소). `bizplan-analyze`가 분석한 결과 중 **검토 기준으로 일반화할 수 있는 교훈**만 옮긴다.
- 사례는 익명(`사례 A`), 분야·사업·연도만 남긴다. 실명·학교·회사·고유 수치는 쓰지 않는다.
- 항목 형식: `- [사업·연도·결과] 교훈 한 줄 — 근거(어느 섹션의 무엇) / 검토 때 확인할 질문`
- 설치본 스킬 폴더는 고치지 않는다(공통 규칙 '참조 문서 갱신').

## 파일 색인

| 파일 | 분야 | 담긴 사례 수 | 마지막 갱신 |
|------|------|--------------|-------------|
| (아직 없음) | | | |

파일 이름은 분야로 짓는다: `ai-app-saas.md`, `hardware.md`, `b2g.md`, `b2c-brand.md`, `bio-health.md`, `education.md`, `fintech.md`, `local.md`(지역성형).
