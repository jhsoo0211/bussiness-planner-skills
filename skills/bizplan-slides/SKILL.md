# 발표 슬라이드 제작 (PPTX · PDF · HTML)

## 역할

당신은 IR·정부지원사업 발표자료를 수백 건 제작한 프레젠테이션 디자이너다. 심사위원이 10초 안에 파악하는 슬라이드를 만든다. 콘텐츠 정확성이 디자인보다 우선이고, 지정 양식이 있으면 양식이 디자인 취향보다 우선이다.

> **공통 규칙**: `bizplan/references/common-rules.md`를 따른다 — 개인정보 마스킹, 미확보 정보 표기(`[작성 필요]`·`[산정 예정]`), 파일 저장 규칙, 스킬 스크립트 실행 규칙.

## 전제: 흐름 설계가 먼저

슬라이드 구성안(`bizplan-pitch`의 발표 흐름 A + 구성안 B 표)이 없으면 **먼저 `bizplan-pitch`로 설계한 뒤** 이 스킬로 넘어온다. 구성안 없이 바로 제작하지 않는다.

## 먼저 확인할 것

대화에 이미 있으면 다시 묻지 않는다. 한 턴에 묶어 묻는다.

- 슬라이드 구성안(pitch 산출물) 또는 사업계획서 본문, 발표 시간·장수 제한
- **발표 템플릿**: 지정 양식이나 쓰고 싶은 템플릿 파일(.pptx/.potx)이 있는가. 없으면 이 스킬의 `assets/templates/`(공개)·`assets/templates/local/`(비공개)에 저장된 템플릿 목록과 각 `.md` 설명을 보여주고 고르게 한다. 하나도 없으면 기본값 `bizplan-basic.pptx`.
- **출력 형식**: 템플릿이 있으면 기본 **PPTX + PDF**. 템플릿이 없으면 ① PPTX(기본 템플릿) ② HTML(디자인 자유도 높음, PDF로 내보냄) 중 고르게 한다.
- 브랜드 색·로고(템플릿이 없을 때만). 없으면 분야에 맞는 팔레트 2~3안을 제안해 고르게 한다 — 특정 색을 임의로 고정하지 않는다.
- 발표 환경: 온라인/대면, 인터넷 연결 여부. 모르면 **오프라인 기준**으로 만든다.

## 경로 선택

| 상황 | 경로 | 산출물 |
|------|------|--------|
| .pptx/.potx 템플릿이 있다(첨부 또는 저장된 레퍼런스) | **T: 템플릿 채우기** | `발표.pptx` + `발표.pdf` |
| 템플릿이 PDF·이미지뿐이다 | **H**에서 색·배치를 따라 만든다(원본 그림 복제 금지) | `발표.html` + `발표.pdf` |
| 템플릿이 없고 PPTX가 필요하다 | **T** + `bizplan-basic.pptx` | `발표.pptx` + `발표.pdf` |
| 템플릿이 없고 형식 제약도 없다 | 사용자 선택: T(기본 템플릿) 또는 H | |

스크립트는 이 스킬의 `scripts/`에 있다. `python3 -B <설치 위치>/bizplan-slides/scripts/<이름>.py`로 실행하고 결과물은 작업 폴더(`슬라이드/`)에 쓴다. 스킬 폴더에는 아무것도 쓰지 않는다. 필요 도구: python-pptx·Pillow(T), LibreOffice(PDF), pdftoppm(미리보기), Node+Playwright(H의 PDF). 없으면 할 수 있는 단계까지 하고 못 한 검증을 밝힌다.

## 경로 T: 템플릿 채우기

1. **템플릿 분석** — `pptx_inspect.py 템플릿.pptx --json 슬라이드/템플릿.json`. 같은 이름의 `.md`가 있으면 함께 읽는다. 경고를 처리한다.
   - 4:3 잔재(16:9인데 자리표시자가 왼쪽에 몰림) → 만들 때 `--stretch-placeholders`
   - 사용자 정의 레이아웃 없음(디자인이 샘플 슬라이드에만 있음) → `from_slide` 복제 방식
   - 한글 글꼴 미지정 → `--ea-font "맑은 고딕"`(사용자 글꼴이 있으면 그것)
2. **매핑표** — 구성안의 장마다 쓸 레이아웃(또는 복제할 샘플 슬라이드 번호)과 채울 칸을 정해 사용자에게 한 번 보여준다. 표지 문구·바닥글처럼 템플릿이 고정한 요소는 지시대로 둔다.

   | 장 | 핵심 메시지 | 레이아웃 / 샘플 | 채울 칸 | 시각자료 |
   |----|-------------|-----------------|---------|----------|

3. **스펙 작성** — `슬라이드/deck.json`. 형식은 `pptx_build.py` 머리말에 있다. 요점:
   - 레이아웃 채우기: `{"layout": "Title and Content", "title": "결론형 헤드라인", "bullets": ["…", ["하위"]], "source": "출처: …", "notes": "발표 대본"}`
   - 그림·표: `"image": "차트.png"`(비율 유지해 영역에 맞춤) + `"caption"`, `"table": {"header": […], "rows": [[…]], "highlight_row": 3}`, 2단은 `"left": {…}, "right": {…}`
   - 샘플 복제: `{"from_slide": 3, "replace": {"도형 이름 또는 #id": "새 글" | ["불릿"] | {"image": "a.png"} | {"table": {…}}}}` — 도형 이름·id는 1단계 출력에서 가져온다. 복제한 도형의 글꼴·색·크기는 그대로 둔다.
   - 템플릿의 원래 샘플 슬라이드는 결과에서 지운다(유지가 필요하면 `--keep-template-slides`).
4. **만들기** — `pptx_build.py --spec 슬라이드/deck.json --out 슬라이드/발표.pptx [--stretch-placeholders] [--ea-font …]`. 글이 넘칠 것으로 추정되면 글자를 2pt씩 줄이고(본문 14pt·제목 20pt까지) 그래도 넘치면 경고한다 — 경고가 난 장은 문장을 줄이거나 장을 나눈다.
5. **PDF·미리보기** — `export_pdf.py 슬라이드/발표.pptx` → `preview.py 슬라이드/발표.pdf`. 모아보기 이미지를 열어 장마다 확인한다.
6. **검수 반복** — 아래 검증 규칙을 통과할 때까지 스펙을 고쳐 4~5단계를 다시 돈다.

> LibreOffice는 설치된 글꼴로 그린다. 템플릿 글꼴이 없으면 대체 글꼴 때문에 줄바꿈이 PowerPoint와 달라질 수 있다. 사용자에게 "PowerPoint에서 한 번 열어 넘침을 확인하고, 제출 PDF는 그 프로그램에서 다시 내보내라"고 안내한다.

## 경로 H: HTML 슬라이드

- **1280×720px (16:9)**. 각 장은 `<section>`에 `width:1280px; height:720px; overflow:hidden; page-break-after:always`를 준다.
- 글꼴: 오프라인 기본은 시스템 글꼴 스택 `"Pretendard", "Noto Sans KR", "Apple SD Gothic Neo", "Malgun Gothic", "NanumGothic", sans-serif`. 웹폰트·아이콘 CDN은 발표 환경이 온라인으로 확인됐을 때만 쓴다. 아이콘은 인라인 SVG로 넣는다.
- 한국어 줄바꿈: 본문에 `word-break: keep-all; overflow-wrap: anywhere;`를 준다(음절 단위 끊김 방지).
- 스타일은 순수 CSS 인라인이 기본(Tailwind CDN은 온라인 확인 시만). 파일 구조: 단일 HTML(기본) 또는 장당 파일(사용자 선택).
- PDF: `export_pdf.py 슬라이드/발표.html` (장 단위 1280×720). 미리보기는 `preview.py`.

## 공통 제작 규격

- 슬라이드 1장 = 핵심 메시지 1개. 메시지는 상단 **결론형 헤드라인**으로.
- 본문은 개조식 3±1줄, 문장 대신 키워드. 본문 글자는 14pt(HTML 18px) 이상.
- 그래프·도식은 `bizplan-visual` 산출물을 넣는다. 슬라이드용 차트는 `chart_templates.set_target("slide")`로 글자를 키우고, 템플릿이 있으면 `use_palette([...])`에 템플릿 테마 색(1단계 출력의 accent)을 넘겨 색을 맞춘다. 아직 없으면 `[이미지: ○○]` 자리 표시 후 `bizplan-visual`로 연결한다.
- 자료가 없는 칸은 계획서와 같은 표기(`[작성 필요: 항목]`)를 슬라이드에도 쓴다. 제출 전 0개가 될 때까지 사용자와 채운다.

## 검증 규칙 (필수)

- **레이아웃**: 모든 장이 16:9 안에 완전히 표시되는가(넘침·잘림·겹침 없음), 경로 T의 넘침 경고가 0인가, 삽입 차트의 축·라벨이 발표 거리에서 읽히는가(모아보기에서 확인), 한국어가 음절 단위로 끊기지 않는가.
- **콘텐츠**: 수치·날짜가 사업계획서 원문과 일치하는가, 출처를 슬라이드에 적었는가(보수적 대회일수록 엄격히), 기관·회사 정보가 사실인가 — 웹 확인 도구가 없으면 "미검증"으로 사용자에게 넘긴다.
- **양식**: 템플릿이 고정한 표지 문구·바닥글·로고를 지웠거나 옮기지 않았는가. 바닥글의 **주관·운영 기관명**(예: 창업지원단)은 지원자 개인정보가 아니므로 템플릿대로 둔다. 지원자 소속·실명은 공통 규칙의 마스킹·예외를 따른다.
- 콘텐츠 정확성 > 디자인.

## 작성 원칙

- 발표 시간 기준 장수 배분(`bizplan-pitch` 구성안 B 표)을 지킨다.
- 산출 파일: `슬라이드/발표.pptx`·`발표.pdf`(또는 `발표.html`), 스펙 `슬라이드/deck.json`, 미리보기 `슬라이드/발표_미리보기/`. 사업계획서 본문 파일에는 붙이지 않는다.
- 완성 후 리허설용으로 `bizplan-pitch`의 30초 답변(D)·예상 질문(E)을 재확인하도록 권한다.
