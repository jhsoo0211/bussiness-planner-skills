# 파싱 결과 → 디자인 적용 분류

시각자료와 PPT가 함께 쓰는 **표현 선택 지침**이다. PSST 순서, 주장–근거, 문제–해결 대응, 관계 유형(R1~R23), 기존 `pattern`·`spec`은 그대로 둔다. 디자인에 맞추려고 논리를 다시 쓰거나 항목 수·순서·비교 축·화살표 방향을 바꾸지 않는다. 관계 판별 기준은 기존 `info-patterns.md`다.

## 1. 디자인을 고르는 순서

1. **지정 양식 → 사용자 지정 테마·브랜드**가 우선이다. 기관 PPT가 있으면 원래 마스터·글꼴·색·레이아웃·로고를 유지한다.
2. 이미 주어진 아이템·고객·발표 목적·원하는 인상을 읽고 테마 후보를 고른다. 업종은 후보 신호이며 `환경=녹색`, `AI=파랑` 같은 고정 규칙이 아니다. 색을 고르기 위해 사업 내용을 추가 추론하지 않는다.
3. `단위.json`의 관계와 패턴을 읽어 **같은 패턴 안의** 구획·라벨·여백·사진 비중·강조 방식을 분류한다. 순서 없는 카드에는 화살표를 추가하지 않는다. 원문에 없는 사진·제품 화면·수치는 레퍼런스에서 가져오지 않는다.
4. PPT와 시각자료에 같은 선택 테마를 전달한다. 사업계획서 인쇄용은 밝은 배경과 본문 가독성을 유지하며, PPT의 배경색을 이미지 전체에 강제로 입히지 않는다.
5. 문맥이 부족하면 중립적인 `mono-line`을 임시 추천하고 이유를 적는다. 브랜드나 원하는 인상이 있으면 그 판단이 우선한다. 결과를 크게 바꾸는 선호가 충돌할 때만 질문한다.

| 후보 테마 | 표현 인상 | 후보를 검토할 문맥의 예 |
|---|---|---|
| `forest-mint` | 차분한 녹색·민트, 얇은 구획 | 환경·돌봄·신뢰·청결 |
| `warm-sand` | 크림·테라코타, 사진과 설명 병치 | 식품·생활·로컬·따뜻함 |
| `plum-soft` | 보라·라일락 구획, 부드러운 카드 | 교육·콘텐츠·창작·친근함 |
| `lime-ink` | 잉크 본문·라임 구획, 선명한 대비 | 제품 중심 IR·대담함 |
| `mono-line` | 흑백·가는 선 | 미니멀·보수적 심사·문맥 부족 |
| `report-blue` / `basic-navy` | 기존 블루 계열 | 사용자가 고른 파랑·기관·산업의 후보 |

## 2. 분류 도우미 — 기존 파서와 독립

`bizplan-slides/scripts/design_advisor.py`는 기존 `suggest_patterns.py --json` 결과를 읽는다. 파서를 재실행하거나 `deck.json`을 다시 쓰지 않는다. 표지·목차·장수·주장·수치·패턴을 바꾸는 기능은 없다.

작업 폴더에 디자인 문맥을 JSON으로 적는다. 실제 대화에서 확인된 내용만 넣고 모르는 필드는 생략한다.

```json
{
  "item": "버려지는 농산물을 활용한 식품",
  "industry": "식품·로컬",
  "audience": "지원사업 심사위원",
  "tone": "따뜻하고 차분한",
  "fixed_template": false
}
```

- `theme`: 명시적 테마 이름 또는 JSON 경로. 사용자가 지정했다면 넣는다.
- `brand_primary`: 확인된 브랜드 원색(6자리 hex). 밝은 색은 강조면의 흰 글자를 읽을 수 있는 같은 계열의 어두운 강조색으로 조정하고 원색과 조정색을 함께 기록한다. 정확한 색 보존이 필수인 지정 양식은 `fixed_template: true`로 처리한다.
- 도우미는 간단한 키워드 후보 검색이다. 신호와 후보를 출력하므로 에이전트가 문맥에 맞는지 확인한다. 키워드 점수로 사업 논리를 평가하지 않는다. 명시적 `--theme`·`--accent`가 문맥의 동일 필드보다 우선한다.

```bash
# 아래 명령은 작업 폴더에서 실행한다. <skills>는 설치된 skills 폴더다.
python3 -B <skills>/bizplan-slides/scripts/design_advisor.py \
  --units 슬라이드/단위.json --context 슬라이드/디자인문맥.json \
  --out 슬라이드/디자인분류.json --md 슬라이드/디자인분류.md \
  --theme-out 슬라이드/선택테마.json

# 기존 deck.json의 내용·패턴을 그대로 렌더한다.
python3 -B <skills>/bizplan-slides/scripts/theme_deck.py \
  --spec 슬라이드/deck.json --theme 슬라이드/선택테마.json --out 슬라이드/발표.pptx
python3 -B <skills>/bizplan-visual/scripts/html_visuals.py 시각자료/spec.json \
  --slide --theme 슬라이드/선택테마.json --out 시각자료/발표
```

matplotlib 대체 경로는 `선택테마.json`의 `colors.series`를 `use_palette()`에 전달한다. 이미지 생성 프롬프트에도 같은 `colors.text`·`colors.primary`를 사용한다. 지정 양식이면 도우미는 `template-preserve`와 참고표만 출력하고 `--theme-out` 파일을 만들지 않는다. 경로 T를 그대로 따른다.

분류표는 `id / 기존 code / 기존 pattern / treatment / reference_keys`를 기록한다. 관계가 미확정(`R5?` 등)이면 추천을 보류한다. 지원하지 않는 패턴을 임의로 다른 패턴으로 바꾸지 않는다. 분류 결과의 보조 필드를 `deck.json` 슬라이드에 복사하지 않는다.

## 3. 미리캔버스 조사 기록과 추가 검색

2026-10-28에 한국어 프레젠테이션 후보 **90개를 검색하고 모아보기로 확인**했다. 일반 사업·IR, 친환경·교육·헬스케어, 식품·로컬관광·AI의 세 검색 묶음이다. 기록은 [design-references.json](../assets/design-references.json)에 있다.

- **30개**는 관찰한 배치 문법을 기존 패턴에 연결했다(`mapped`). 나머지 60개는 탐색 기록(`discovery_only`)이며 자동 추천에 쓰지 않는다.
- 후보당 앞 최대 20쪽의 모아보기 기준이다. 20쪽이 넘는 템플릿의 나머지 페이지, 작은 글자, 편집 가능 여부, 내부 manifest는 확인했다고 주장하지 않는다.
- `template_key`는 재조회 식별자다. 실제 반환된 웹 주소가 없어서 편집 링크를 만들지 않았다. 필요한 경우 미리캔버스 `search_templates(keywords=["key:<template_key>"])`로 다시 찾는다.
- 기존 분류와 참고집으로 표현이 충분하면 새 검색을 생략한다. 사용자가 새 스타일을 요청하거나, 같은 관계를 보존하면서 표현할 참고가 부족할 때만 아이템·필요 패턴으로 추가 조사한다.
- 연결된 미리캔버스 도구의 안내를 읽고 검색·미리보기 조회만 한다. 구조를 더 확인해야 하면 해당 후보 페이지를 직접 확인한 뒤 관찰 수준을 기록한다. 검색 실패 시 기존 참고집으로 계속하고 미확인 부분을 표시한다.
- 저장소에는 식별자·조사일·관찰 메모·직접 작성한 테마/코드만 남긴다. **원본 PPT·PDF·이미지·썸네일·사진·로고·문구·원시 manifest 전체는 내려받거나 커밋하지 않는다.** 디자인 생성·드라이브 업로드도 레퍼런스 조사에 필요하지 않다.

## 4. 디자인 분류용 프롬프트

아래 지시를 visual·slides 디자인 선택과 이미지 프롬프트 작성에 공통 적용한다.

```text
기존 PSST 내용과 확정된 정보 관계는 고정 입력이다.
원문·숫자·출처·주장–근거·문제–해결 대응·항목 순서·관계 code·pattern·spec을 보존한다.
디자인 때문에 화살표, 위계, 포함 관계, 비교 기준, 장 순서를 새로 만들거나 바꾸지 않는다.

입력: 확인된 아이템 / 고객 / 사용처 / 원하는 인상 / 지정 양식·브랜드 / 기존 파싱 결과.
선택: 지정 양식과 브랜드를 우선하고, 사업 문맥에 맞는 색상·글자 위계·여백·구획·강조 방식만 고른다.
기본 파랑·남색을 반복하지 않는다. 업종은 색상 후보 신호로만 쓴다.
원문 정보를 채우거나 삭제하지 말고, 필요한 보유 이미지가 없으면 미확보 상태를 유지한다.

같은 pattern을 표현하는 기존 디자인과 조사한 미리캔버스 참고 메모를 우선 사용한다.
기존 구조와 다르게 꾸며야 해도 논리 관계와 방향은 유지한다.
추가 참고가 필요하면 해당 관계를 유지하는 배치 사례만 조사하고 관찰한 범위를 적는다.
레퍼런스의 파일·사진·텍스트·로고는 복제하지 않는다.

출력: 선택 테마와 이유 / 단위별 기존 code·pattern / 표현 추천 / 참고 식별자 / 확인이 필요한 부분.
결과는 디자인분류 파일과 선택테마 파일로 분리한다. 기존 원문·파싱·덱 파일을 재작성하지 않는다.
이미지 생성에는 선택테마의 색을 실제 hex로 채워 쓰고, 정확한 도식 라벨·수치는 기존 규칙대로 검수한다.
```

## 5. 적용 검수

- 디자인 적용 전후 원문·`단위.json`·`deck.json`이 같은가.
- 같은 정보 관계가 유지되고 순서 없는 항목에 인과·순서가 추가되지 않았는가.
- PPT·차트·이미지 프롬프트의 강조색이 같은 선택테마를 쓰는가.
- 모든 장을 렌더해 한글·대비·잘림·겹침을 확인했는가.
- 파일 목록에 미리캔버스 원본·썸네일·미디어가 포함되지 않았는가.
