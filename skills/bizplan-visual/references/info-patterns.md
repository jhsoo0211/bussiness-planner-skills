# 정보 유형 → 시각화 구조 (파싱 기준)

사업계획서 문장을 슬라이드·도표로 옮길 때 **무엇을 어떤 형식으로 보여줄지**를 정하는 단일 기준이다. 문서(사업계획서 본문의 표·그림)와 발표(PPTX·HTML)가 같은 판단을 쓴다.

형식은 주제가 아니라 **정보 사이의 관계**로 정한다. 같은 '시장' 내용이라도 관계에 따라 형식이 달라진다.

- 포함 관계(전체 ⊃ 유효 ⊃ 목표)면 시장 규모 원
- 시간에 따른 변화면 추이 그래프
- 경쟁자와의 위치면 포지셔닝 맵

슬라이드 패턴 이름(`type`)은 `bizplan-slides/scripts/theme_deck.py`의 패턴과 같다(`--catalog`로 필드 확인). 실제 템플릿에서 뽑은 장 구성 예는 `bizplan-slides/references/blueprints.md`에 있다.

## 1. 파싱 절차

1. **단위 나누기** — 소제목(□) 하나, 표 하나, 목록 하나, 숫자 묶음 하나가 정보 단위 1개다. 단위마다 원문 위치(목차 번호·소제목)를 적는다. `bizplan-slides/scripts/suggest_patterns.py 사업계획서.md`가 단위·신호·추천 패턴 초안을 뽑아 준다. 초안이므로 아래 표로 확인한다.
2. **관계 판별** — 2절의 결정 순서와 3절의 신호표로 관계 유형(R1~R23)을 정한다.
3. **필드 옮기기** — 패턴의 필드에 원문을 옮긴다.
   - 줄이기만 하고 새 사실·수치·형용사를 더하지 않는다.
   - 숫자는 원문 그대로(단위·시점 포함) 옮긴다.
   - 원문에 없는 값은 `[작성 필요: 무엇]`으로 남긴다.
4. **수용량 점검** — 4절 한도를 넘으면 장을 나누거나, 항목을 묶거나, 표(`table`)나 부록으로 내린다. 한도를 넘는 항목을 잘라 버리지 않는다.
5. **헤드라인** — 단위의 결론을 결론형 한 문장으로 써 `title`에 넣는다. 근거는 `source`, 한 줄 보충은 `lead`, 바닥 결론은 `callout`이다.
6. **대조** — 만든 뒤 `bizplan-slides/scripts/deck_check.py 발표.pptx --against 사업계획서.md`로 슬라이드의 수치가 원문에 있는지 확인한다.

파싱표(작업 폴더 `슬라이드/파싱표.md`) 형식:

| # | 원문 위치 | 정보 단위(요지) | 관계 유형 | 판별 신호 | 패턴 | 항목 수 | 필드 메모 |
|---|-----------|-----------------|-----------|-----------|------|---------|-----------|
| 1 | 1-1 □2 | 복약 누락 원인 4가지 | R4 중심-주변 | '요인' + 형제 항목 4 | radial | 4 | center=복약 누락 |

## 2. 결정 순서 (모호할 때 위에서부터)

1. **숫자가 주인공인가?**
   - 이름 붙은 숫자 2~4개 → R5
   - 시간축 → R6
   - 대상끼리 → R7
   - 합이 100% → R8
   - 포함 관계 → R9
2. **시간이 주인공인가?**
   - 날짜 + 사건 → R14
   - 과업 × 기간 → R15
3. **둘 이상을 견주는가?**
   - 기준 여러 개 → R10
   - 전·후 → R11
   - 두 축 → R12
4. **순서를 바꾸면 틀리는가?**
   - 그렇다 → R13 단계
   - 아니다 → R2 병렬. 순서 없는 항목을 화살표로 잇지 않는다(가짜 인과).
5. **항목들이 한 결론으로 모이는가?** → R3. **한 중심을 둘러싸는가?** → R4
6. **라벨 → 내용의 쌍인가?** (리스크 → 대응, 질문 → 답, 문제 → 해결) → R19
7. 나머지 한 문장 주장 → R1, 설명 → 개조식(`bullets`).

헷갈리는 예:

- "3단계 로드맵(2026~2028)": 연도가 주인공이면 R14(`timeline`), 단계 내용이 주인공이면 R13(`process`, `label`에 연도).
- "경쟁사 3곳 가격": 지표 하나면 R7(막대, 자사 강조). 기준이 여러 개면 R10(비교표).
- "문제 3개와 각각의 해결": R19(`rows`, label=문제, title=해결). 문제만 3개면 R2.

## 3. 관계 유형 신호표

| 코드 | 관계 유형 | 원문 신호 (이런 말·형태가 보이면) | 슬라이드 패턴 | 문서(A4) 표현 |
|------|-----------|-----------------------------------|---------------|----------------|
| R1 | 단일 주장 | "즉·결국·핵심은", 소제목 아래 한 문장 결론 | `statement` / 다른 장의 `callout` | 소제목 아래 굵은 요약문·테두리 상자 |
| R2 | 병렬 항목 | "첫째·둘째", "세 가지", 같은 문형의 □·○ 형제 2~4개 | `cards` (5~6개면 2줄 또는 `rows`) | 3~4열 표 또는 번호 상자 |
| R3 | 병렬 → 결론 수렴 | 병렬 항목 뒤 "따라서·이에·이를 위해" 결론 | `cards` + `converge` + `callout` | 3칸 표 + 아래 결론 상자(화살표) |
| R4 | 중심-주변 | 핵심 개념 하나를 둘러싼 요인·이해관계자·니즈 | `radial` | 중심 원 + 4방향 상자(냅킨AI) 또는 2열 표 |
| R5 | 핵심 수치 | 숫자+단위 2~4개, 숫자마다 이름("이행률 38%") | `kpi` (달성률이면 `percent`) | 숫자 강조 상자, 표의 굵은 수치 |
| R6 | 시간 추이 | 연도·분기·월별 값 3개 이상, "성장·증가·CAGR" | `chart` line/column | `growth_line` / 막대 |
| R7 | 대상 간 크기 비교 | 같은 지표의 여러 대상 값, "대비 n배·n% 저렴" | `chart` bar/column + `highlight` | `bar_compare` (자사 색 강조) |
| R8 | 구성비 | 합이 100%인 비율, "비중·점유율·구성" | `chart` doughnut | 도넛·누적 막대 |
| R9 | 포함(시장 규모) | TAM·SAM·SOM, 전체 ⊃ 유효 ⊃ 목표 | `tam` | `tam_sam_som` 동심원 + 산식 표 |
| R10 | 기준별 대조 | "기존 vs", "경쟁사 대비", O/△/X, 비교 기준 목록 | `compare` (`criteria`) 또는 `table` | 비교표(자사 열 강조, 실측치 병기) |
| R11 | 전 → 후 | "도입 전/후", "기존에는 … 이제는", As-Is/To-Be | `before_after` | 2열 표 + 화살표 |
| R12 | 2축 위치 | 두 기준으로 본 경쟁자 위치, "사분면" | `positioning` | `positioning_map` (축 선정 근거 캡션) |
| R13 | 순서 단계 | "1단계·STEP", "→", "먼저·다음·마지막", 절차·사용 흐름 | `process` | STEP 도식(상태 배지) |
| R14 | 시점 이정표 | 날짜 + 사건 3~6개, "완료·진행·예정", 연혁 | `timeline` (`status`) | 연혁 표·타임라인 |
| R15 | 과업 × 기간 | 과업마다 시작·끝 월, "M1~M3", 추진 일정표 | `gantt` | `gantt` 또는 추진 일정 표 |
| R16 | 다속성 기록 | 행마다 같은 속성 3개 이상(비목·산출근거·금액) | `table` | 표 그대로(`check_tables.py` 검산) |
| R17 | 양면 금액 | 수입/지출, 정부지원/자기부담 | `table` + `tables` 2개 | 표 2개 또는 한 표의 구분 열 |
| R18 | 2×2 판단 | SWOT, 강점·약점·기회·위협 | `swot` | 2×2 표 |
| R19 | 라벨-내용 쌍 | 리스크 → 대응, Q → A, 문제 → 해결, 분기 → 계획 | `rows` (+ `callout`) | 2열 표 |
| R20 | 위계 체계 | 비전·미션·전략 축·기반, "체계" | `pillars` | 체계도 표 |
| R21 | 사람 | 이름(○○ 마스킹)·역할·경력 | `team` | 팀 구성 표(사진·이력·증빙) |
| R22 | 증거물 | 사진·화면·실물·의향서·인증서 | `image` (+ 주장 옆에 둔다) | 그림 + 결론형 캡션 |
| R23 | 구분·안내 | 목차·대단원 | `toc` / `section` | 목차·장 제목 |

패턴이 없는 관계(돈·물자가 도는 BM 순환도, 기관 간 협력 관계도)는 그림으로 만든다. `bizplan-visual`의 냅킨AI나 이미지 생성을 쓰고, 결과를 `image`로 넣는다. 흐름이 한 방향 일직선이면 `process`로 충분하다.

## 4. 수용량 (16:9 슬라이드 기준, 본문 12.5~16pt)

| 패턴 | 항목 수 | 항목당 글(한글 기준) | 넘칠 때 |
|------|---------|----------------------|---------|
| `bullets` | 3±1줄(최대 6) | 줄당 40자 | 장 나누기 또는 `rows` |
| `cards` | 2~4(최대 6) | 제목 12자 · 본문 60자(3장일 때), 40자(4장일 때) | 둘로 나누기 / `rows` |
| `radial` | 3~6 | 제목 10자 · 설명 25자 | 2단계로 묶기 |
| `kpi` | 2~4 | 값 8자 · 이름 10자 · 설명 30자 | 덜 중요한 수치는 `table`로 |
| `process` | 3~5(최대 6) | 제목 10자 · 설명 40자 | 단계 묶기(하위 단계는 설명에) |
| `timeline` | 3~6 | 시점 8자 · 제목 12자 · 설명 30자 | 연도별로 장 나누기 |
| `gantt` | 행 8(최대 10) × 기간 12칸 | 과업명 10자 · 막대 글 12자 | 과업군으로 묶거나 반기별로 나누기 |
| `table` | 행 8 × 열 5 | 칸 20자 | 본문엔 합계·핵심 행만, 전체는 부록 |
| `compare` | 기준 3~6 | 칸 25자 | `table`로 |
| `rows` | 2~5(최대 6) | 제목 25자 · 설명 60자 | 장 나누기 |
| `swot` | 칸마다 2~4 | 항목 20자 | 상위 2개만, 나머지는 문서에 |
| `tam` | 3층 고정 | 층위 근거 40자 | 산식은 `notes`나 부록 |
| `team` | 1~4명 | 경력 2~4줄 | 협력 기관은 `rows`로 따로 |
| `positioning` | 경쟁자 3~6 | 이름 8자 | 대표 경쟁자만 |

- 문서(A4)의 표·그림은 위 한도의 약 2배까지 받는다. 그래도 그림 한 개에 메시지는 하나다.
- `theme_deck.py`는 넘침을 추정해 글자를 줄이고(본문 최소 10.5~13pt), 그래도 넘치면 '약 N자 줄이기' 경고를 낸다. 경고가 난 장은 위 '넘칠 때'대로 고친다.

## 5. 필드로 옮기는 예

원문 (1-1 배경):

> □ 만성질환 다제 복용이 늘었다 … □ 혼자 사는 고령자가 늘었다 … □ 보호자는 확인할 수 없다 … 따라서 확인·기록·공유 도구가 필요하다.

→ R3 (병렬 3 + "따라서" 결론):

```json
{"type": "cards", "title": "세 가지 변화가 '확인 도구'의 필요로 모인다", "converge": true,
 "items": [{"title": "복용 약 증가", "body": "만성질환 다제 복용 증가"},
           {"title": "혼자 사는 고령자", "body": "옆에서 챙길 사람이 없다"},
           {"title": "보호자의 불안", "body": "원격으로 확인할 수 없다"}],
 "callout": "복약을 **확인·기록·공유**하는 도구가 필요하다", "source": "원문 1-1"}
```

원문 (3-3 일정표, 마크다운 표 `| 추진 내용 | 기간 | 세부 내용 |`의 행 "MVP 고도화 | 2026.01~03 | 음성 알림") → R15:

```json
{"type": "gantt", "title": "협약 8개월 안에 실증까지 끝낸다", "periods": ["1월","2월","3월","4월","5월","6월","7월","8월"],
 "rows": [{"task": "MVP 고도화", "start": 1, "end": 3, "label": "음성 알림", "status": "진행"}]}
```

원문 (시장 규모: "TAM 2,830억 원(통계청 …), SAM 640억 원(…), SOM 12억 원(…)") → R9. 값과 근거를 층위마다 옮기고, 출처는 `source`에 둔다.

```json
{"type": "tam", "title": "3년 안에 확보할 목표 시장은 12억 원", "items": [
  {"value": "2,830억 원", "desc": "국내 복약 관리 서비스 전체"},
  {"value": "640억 원", "desc": "만성질환 1인 고령 가구 × 연 이용료"},
  {"value": "12억 원", "desc": "2개 광역시 복지관 연계 3년 목표"}], "source": "통계청 … / 자체 산정"}
```

## 6. 문서(사업계획서)에서 자주 쓰는 증명 형식

섹션 설계도(`bizplan/references/section-blueprints.md`) 3절의 시각자료 슬롯에 쓰는 형식이다. 슬라이드 패턴과 같은 관계 유형을 문서용으로 옮긴 것이다.

| 형식 | 관계 유형 | 블록 | 만드는 법 |
|------|-----------|------|-----------|
| 실물 증빙 격자 | R22 증거물 | B6 준비 정도 · B14 시설 | 마크다운 표 한 줄에 그림 2~4개, 다음 줄에 캡션(무엇 · 언제). `md_to_docx.py`가 칸 너비에 맞춘다 |
| 번호 화면 흐름 ①②③ | R13 단계 + R22 | B7 구체화 | 화면 캡처 3~4장 + 번호 라벨, 단계마다 시각·상태. 동작하지 않는 화면은 '계획' 표기 |
| 비교표(확인 경로 열) | R10 기준별 대조 | B8 차별 | 실명 3+ · 대체재 · 불리 축 1+ · 확인 경로 열 · 자사 열만 강조 |
| 1차 고객 수 깔때기 | R9 포함(시장 규모) / R13 | B5 시장·고객 | 동심원·깔때기 + 오른쪽 산식(모집단 × 발생률 × 의향 × ½) + 아래 한 줄 메시지 |
| 페르소나 카드 | R21 사람 | B5 고객 특성 | 정의 · 해시태그 4 · 사용 장면 · 인용 3 · 검증 n/N |
| BM 구조도(금액 화살표) | R4 중심-주변 / R13 | B10 BM | 주체 3개 이내, 돈은 실선, 가치는 점선, 화살표마다 금액 |
| 고객 확보 퍼널 | R13 단계 | B11 진입 | `chart_templates.funnel` — 단계 인원 · 구간 전환율 · 근거 라벨 |
| 손익 콤보 | R6 시간 추이 | B12 3지표 | `chart_templates.pnl_combo` — 매출 막대 + 총비용·영업이익 선, ★ 흑자 전환 |
| 3지표 카드 | R5 핵심 수치 | B12 | 매출 · 투자 · 고용 수치 카드 3개 + 각 근거 한 줄 |
| 인과 로드맵 | R15 과업×기간 | B13 | 행 = 성과 축(7개 이내), 칸 = 과업 → 산출물 → KPI → 고객 → 매출, 변곡점 ★ |

## 7. 흔한 실수

- 숫자를 카드 본문에 묻는다 → `kpi`로 꺼내 크게 보여준다(숫자는 크게, 단위는 작게).
- 순서 없는 항목을 화살표로 잇는다 → `cards`. 화살표는 순서나 인과가 실제로 있을 때만 쓴다.
- 한 장에 관계 두 개(추이 + 구성비)를 넣는다 → 장을 나누거나 `chart` + `points`로 한쪽을 글로 내린다.
- 단위가 다른 숫자를 한 차트에 넣는다 → 차트를 나눈다. 차트 값은 숫자만, 단위는 `unit`에 쓴다.
- 비교표 기준을 자사에 유리한 것만 고른다 → 기준을 원문 근거(고객 인터뷰 상위 요구 등)로 정하고 `source`에 적는다.
- 시각화하면서 원문에 없는 수치·형용사("업계 최초", "압도적")를 더한다 → 금지한다. `deck_check.py`로 대조한다.
- 미확보 값을 그럴듯한 숫자로 채운다 → `[작성 필요: 무엇]`을 그대로 둔다. 렌더러가 개수를 센다.
- 표가 넘쳐 글자를 9pt까지 줄인다 → 본문엔 핵심 행만 두고 전체 표는 부록 장이나 문서로 보낸다.
