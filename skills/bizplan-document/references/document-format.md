# 완성 문서 서식

> `bizplan-document`(완성 문서 모드)가 쓰는 문서 형식이다. 정부지원사업 문서형 양식(예비창업패키지 등)의 칸 구조를 따르면서,
> 글은 **경어체 서술 문단**으로, 절마다 **그림·표·사진**을 최대한 붙여 완성본처럼 만든다.
> 무엇을 써야 하는지(블록 B1~B14의 필수 내용·숫자 규칙)는 [섹션 설계도](../../bizplan/references/section-blueprints.md)를 그대로 따른다.
> 이 문서는 **어떻게 보이고 어떻게 읽히게 쓰는가**만 정한다.

## 1. 문서 순서와 기본 목차

공고 양식이 있으면 양식의 목차와 칸 이름을 쓴다(섹션 설계도 4절 매핑으로 블록을 옮긴다). 양식이 없으면 아래 목차를 쓴다.

| 순서 | 마크다운 | 담는 블록 | 핵심 |
|------|----------|-----------|------|
| 제목 | `# 창업사업화 지원사업 사업계획서 (예비 창업자)` | — | 사업 이름에 맞춰 바꾼다 |
| 개요 | `## □ 창업아이템 개요(요약)` + ` ```개요 ` 블록 | B1 · B2 | 2절 |
| 1장 | `## 1. 문제인식 (Problem)` | | |
| | `### 1-1. 창업아이템의 개발 동기 / 개발 추진 경과(이력)` | B3 | 사회적 문제 · 개인적 배경 |

| | `### 2-1. 창업아이템의 개발 방안 / 진행(준비) 정도` | B6 · B7 | 산출물 · 만들기/사기 · 진행 정도 · 시설 · 기술 보호 |

| | `### 4-2. 팀 현황 및 보유역량` | B14 | 팀원 표 · 시설 구성 · 업무 파트너 |

- 양식이 일반현황(신청 분야·팀 구성 현황 등) 표를 요구하면 개요 앞에 `## □ 일반현황`과 보통 표로 둔다.
- 쪽 수는 줄이지 않는다. 공고 분량과 비교한 결과와 줄일 후보는 작성가이드에 적는다(5-3절).

## 2. 개요 양식 블록

개요는 이름표 칸이 있는 양식 표다. 마크다운에는 ` ```개요 ` 블록으로 쓰고, 변환기(`--style form`)가 표로 만든다.
- 이름표 열은 회색이다.
- 명칭·범주는 한 줄에 놓는다.
- 나머지 칸은 쓴 순서대로 한 줄씩 넓게 놓는다.
- 이미지는 2개씩 그림 줄과 캡션 줄로 놓는다.

````
```개요
명칭: 서비스 이름(가칭이면 표시)
범주: 제품·서비스 범주 한 줄
소개:
  ○ 한 줄 소개 — 누구의 무슨 문제를 무엇으로 줄이는 **서비스 이름**
  - 사실 한 줄(문제의 크기·대상)
  - 사실 한 줄(작동 방식)
  ○ 1차 산출물 : ○○ / 2차(계획) : ○○
진출 목표시장:
  ○ 1차 시장 : ○○ ○○건(시점·출처)
  - 결제자 · 1차 고객 수 산식 한 줄
경쟁사 대비 차별성:
  ○ 차별점 1 — 한 줄
  - 근거 한 줄
  ○ 차별점 2 — 한 줄
산출물 및 개발단계:
  ○ 협약 기간 산출물 : ○○
  - 현재 단계(완료 · 진행 · 예정)
이미지: 시각자료/a.png = 제품·화면 사진 캡션 | 시각자료/b.png = 시제품·구조 캡션
```
````

- 키는 줄 맨 앞에 `키: 값`으로 쓰고, 여러 줄 값은 두 칸 이상 들여 쓴다.
- **칸과 블록의 대응**(섹션 설계도 B1·B2의 'PSST 요약'을 이 칸들로 채운다): 소개 = 한 줄 소개(B1) + 아이템 개요 · 문제 / 진출 목표시장 = 성장(1차 시장·결제자) / 경쟁사 대비 차별성 = 실현(차별) / 산출물 및 개발단계 = 실현(준비 정도) · 일정. 양식에 팀·사업비 칸이 있으면 키를 더한다.
- `○` 줄은 칸 안의 굵은 헤드라인이고, `-` 줄은 작은 사실 줄이다.
- 칸마다 `○` 1~2개, 사실 줄은 2~3개까지 쓴다.
- **이미지 칸**(폭 약 70mm)에는 실물 사진·화면 캡처를 먼저 넣는다.
  - 없으면 반폭 그림을 만든다: spec에 `"size": "half"`를 단 `screens`(화면 2개), `photos`(1~2칸), `flow`(3단계 이하).
  - 반폭은 폭 430px로 그려 70mm 칸에서 가장 작은 글자가 6.5pt 안팎이고, 높이 62mm를 넘으면 렌더러가 `[확인]`을 낸다.
  - 본문용 그림(폭 860px)이나 SVG 그림(막대·TAM·BM)을 그대로 넣지 않는다 — 칸 안에서 글자가 3~4pt로 줄어 읽히지 않는다.
- **개요는 한 쪽에 넣는다**(행은 쪽에서 갈라지지 않아 넘치면 이미지 줄이 통째로 다음 쪽으로 간다).
  - 제목 줄 24자 안, 명칭·범주 각 16자 안(좁은 칸)
  - `○` 줄은 한 줄(40자 안팎), 칸마다 `○` 1~2개, `○`마다 사실 줄 2개까지
  - 넘치면 사실 줄 → 두 번째 `○` 순서로 줄인다
- 양식에 칸이 더 있으면(팀 구성·사업비 등) 같은 방식으로 키를 더한다.

## 3. 블록 문법

```
#### ○ 주제구                ← 굵게 + 밑줄. 블록 하나가 증명하는 것
##### 소주제                  ← '- 소주제' 굵게. 블록 안의 논점 2~4개
경어체 서술 문단 2~4문장 — 핵심어 **굵게**, 결정 문장 하나만 [밑줄]{.underline}
![결론 문장](시각자료/<id>.png)   ← 그림 · 표 · 사진 격자
- 근거 줄(필요할 때만)  /  1) 2) 3) 계획 목록
※ 주석 한 줄(작게)
(출처: 기관, 연도) · (확인 경로: …)    ← 오른쪽 작게
```

- `####`는 소절 번호(`#### 3-1-1. …`)와 주제구(`#### ○ …`)에 함께 쓴다. 변환기는 `○`로 시작하는지로 둘을 가른다.

| 요소 | 규칙 |
|------|------|
| 이끔말 | 그림·표 바로 앞에는 **한 줄짜리 이끔말**(90자 안, 예: "추진 경과와 남길 증빙은 다음과 같습니다.")을 둔다. 변환기는 짧은 앞 문단만 그림과 같은 쪽에 묶는다 — 긴 문단 바로 뒤에 큰 그림을 두면 문단째 넘어가 쪽 절반이 빈다. 표와 그림이 함께 있으면 표를 먼저 둔다 |
| 주제구 `#### ○` | 주제를 정하는 이름표이자 결론이다. 라벨("사회적 문제")도 되지만 결론형("첫 고객은 ○○ ○○곳이다", "협약 기간 매출 목표 : ○○원")이면 더 좋다. 숫자가 있으면 넣는다 |
| 소주제 `#####` | 주제구 아래 논점을 2~4개로 나눈다. 명사구로 짧게 쓴다(예: "대표의 현장 경력 ○년", "기존 지원 사업의 한계") |
| 문단 | 소주제마다 2~4문장. 한 문장은 2줄 이내, 숫자는 문단당 2~3개까지(섹션 설계도 1-3) |
| 계획 목록 | 생산·디자인·영업·법인 같은 실행 계획은 `1) 2) 3)` 번호 목록으로 쓴다. 항목마다 시점을 넣는다 |
| 채널 줄 | 진출 방안의 채널 문단은 `→ 기대 매출 : 약 ○○원 (산식)`으로 끝낸다. 산식은 수량 × 단가, 채널 합은 3-2-2 매출 목표와 같아야 한다 |
| 목표 주제구 | 3-2-2는 `#### ○ 매출 목표 : ○○원` · `#### ○ 고용 목표 : ○명` · `#### ○ 투자 유치 : ○○원`처럼 목표 숫자를 주제구에 둔다 |
| 투자 조건 | 투자는 `- 투자조건` 아래에 집행 조건(마일스톤) · 방식 · 기업가치 · 상환·회수 계획을 한 줄씩 쓴다. 약정이 없으면 '접촉 계획'으로 쓰고 금액을 지어내지 않는다 |
| 주석 | `※`로 시작하는 줄은 작게 찍힌다. 범위·정의·용어 풀이만 쓴다 |
| 출처 | `(출처: …)`·`(확인 경로: …)` 줄은 오른쪽에 작게 찍힌다. 그림 안 출처와 같은 값이다 |

## 4. 말투

- **경어체 서술**로 쓴다.
  - 어미: "~습니다 · ~입니다 · ~예정입니다 · ~하겠습니다"
  - 표·근거 줄·개요 칸만 명사형 개조식(~함·~임, 체언)을 쓴다.
- **1인칭은 사람 이야기에만 쓴다.**
  - 1-1 개인적 배경과 4장에서 "대표자인 저는", "저희 팀은"을 쓴다.
  - 시장·제품·계획은 사실을 주어로 쓴다("○○ 시장은 …", "필터 엔진은 …").
- **잇는 말**("이에 따라 · 이러한 경험을 통해 · 다만 · 또한")은 문단 첫머리에 쓴다. 같은 말을 이어서 반복하지 않는다.
- **다짐 문장**은 장마다 한 번까지 쓴다. 근거 문단 바로 뒤에만 둔다(예: "M8까지 첫 유료 계약을 반드시 만들겠습니다").
- **형용사 대신 숫자**를 쓴다. "다양한·혁신적인·압도적인"은 횟수·기간·금액으로 바꾼다.
- **블라인드:** 사람 이름·학교·직장은 `○○`로 쓴다. 판매처 담당자는 직함까지만 쓴다(예: "○○ MD").

| 고치기 전 | 고친 뒤 |
|-----------|---------|
| 다양한 마케팅 업무 경험과 노하우가 있음 | 대표자인 저는 브랜드 마케팅 팀장으로 **○년** 일하며 신제품 출시 **○건**을 맡았습니다. |
| 시장이 성장하고 있어 기회가 큼 | ○○ 시장은 **○○억 원**(○○, 2025)이며, 그중 ○○ 세그먼트만 소비가 늘고 있습니다. |
| 온라인 판매 예정 | 기존 입점 경험이 있는 ○○·○○ 두 곳에서 판매를 시작합니다. **→ 기대 매출 : 약 ○○원 (월 ○○개 × ○○원 × ○개월)** |
| 꼭 성공시키겠습니다(근거 없이) | 협약 기간 PoC 4건의 결과로 M8 첫 유료 계약을 반드시 만들겠습니다. (근거 문단 뒤 한 번) |

## 5. 장별 흐름

### 5-1. 절마다 이어지는 순서

| 절 | 흐름 |
|----|------|
| 1-1 | `○ 사회적 문제`: 구조적 문제 + 공적 통계 → 기존 해법(지원 사업·제품)이 통하지 않은 사실 / `○ 개인적 배경`: 대표 경력(기간·횟수) → 직접 겪은 장면 → 팀원 배경 → 실물(포트폴리오·참여 확인 사진 격자) |
| 1-2 | 문제의 근본 원인 하나 → 우리 해법이 그 원인을 어떻게 푸는가 → 비슷한 성공 사례 표(있으면) → 다짐 한 문장 |
| 1-3 | `○ ○○ 시장`: 규모(산식·출처) → 세분화 표(정체 vs 성장, 고른 칸 표시) → 1차 고객 수(모집단 × 발생률 × 의향 ½) → 고객 특성(페르소나) |
| 2-1 | `○ 협약 기간 내 완성할 것`: 제품·기능 표 → 만들기/사기 표(기성품·외주·자체) → 현 시점 진행 정도(완료·진행·예정 + 실물 사진) → 사업장·시설 준비(사진 격자 + 캡션) / `○ 기술 보호` |
| 2-2 | `○ 차별점 n`마다 근거(공공 연구·인증·실측) → `○ 지원 인프라`(쓸 수 있는 시설·지원) → `○ 우리 팀만의 강점`(팀의 판매·입점·운영 이력) → 실명 비교표(불리한 축 포함) |
| 3-1-1 | BM 구조도(누가 누구와 무엇을 주고받는가) → 수익원 표 → 매출 산식 한 줄 |
| 3-1-2 | `○ 오프라인 판매`·`○ 온라인 판매` 등 채널마다 `##### 채널` + 문단 + `→ 기대 매출` → 판매처·담당 표 → 퍼널 |
| 3-2-1 | `○ 사업 로드맵`: 생산·디자인·마케팅·법인/투자·확장 계획을 `1) 2)` 목록으로 → 로드맵 그림 → `○ 사업 추진 일정(전체)` 표 |
| 3-2-2 | `○ 매출 목표`(채널별 표, 합계 = 목표) → `○ 고용 목표`(인력 표) → `○ 투자 유치`(조건 목록) → `○ 사업 추진 일정(협약 기간 내)` 표 + 간트 |
| 3-3 | `○ 자금 소요 계획`: 비목별 산식 줄("인건비 : ○인 × 월 ○○원 × ○개월 = ○○원") → 사업비 집행 표(합계 = 정부지원금) / `○ 추가 자금 조달`: 자기자본·투자 |
| 4-1 | `○ 대표자 경력 사항`: 이전 → 현재(직장명 ○○) + 이 문제와 맞닿은 경험 한 문장 |
| 4-2 | `○ 팀원 구성` 표(순번·직위·담당 업무·보유역량·구성 상태) → `○ 시설 구성`(사진 격자) → `○ 업무 파트너` 표(협력 시기에 조건부 시점 가능) |

### 5-2. 숫자가 다시 나오는 자리

같은 값은 개요 → 1-3 → 3-1 → 3-2-2 → 3-3에서 같은 단위로 다시 나온다(숫자 등록부 한 줄). 채널 기대 매출의 합은 매출 목표와 같다. 비목의 합은 정부지원금과 같고, 투자 금액은 3-2-2와 3-3-2에서 같다.

### 5-3. 분량

쪽 수는 줄이지 않는다. 빌드 보고(`build_document.py --pages-limit N`)의 쪽 수를 작성가이드 '분량' 절에 적는다. 공고 분량을 넘으면 줄일 후보를 효과 순으로 적는다.
- 겹치는 그림(같은 숫자를 다시 보이는 그림)
- 본문 글자 크기
- 사진 격자 줄 수
- 부록으로 옮길 표

## 6. 그림 배치표 (최대)

## 7. 표 서식

- 머리행은 연노랑, 짧은 칸은 가운데 정렬이다(변환기가 칠한다). 머리행 이름은 명사로 짧게 쓴다.
- **사진 격자**: 마크다운 표 첫 줄에 그림 3~4개, 다음 줄에 캡션을 둔다. 캡션은 굵게·가운데로 찍힌다.
  ```
  | ![](사진/a.jpg) | ![](사진/b.jpg) | ![](사진/c.jpg) | ![](사진/d.jpg) |
  |---|---|---|---|
  | 화면 설계 · 2026.10 | 시제품 · 2026.○ | 현장 테스트 · 2026.○ | 협력 확인서 · 2026.○ |
  ```
- 팀원·파트너·판매처 표의 사람 이름·학교·직장은 `○○`로 쓴다.
- **사진 경로**: 본문 마크다운의 경로는 `사업계획서.md` 기준(`사진/a.jpg`)이고, spec의 `src`는 spec 파일 폴더 기준(`../사진/a.jpg`)이다.
- 합계 행이 있는 표는 `check_tables.py`가 검산한다.

## 8. 품질 기준

서식을 따르되 숫자와 근거는 스킬 기준을 지킨다.
- 숫자는 숫자 등록부 값만 쓴다. 미확보 값은 `○○` + 산식 + 확보 계획으로 둔다.
- 매출·인건비·비목은 산식 줄(수량 × 단가 × 기간)로 쓰고, 합계를 검산한다(채널 합 = 매출 목표, 비목 합 = 정부지원금).
- 경쟁은 실명으로 3곳 이상 비교하고, 우리가 불리한 축과 확인 경로를 넣는다.
- 의향·전환율은 보수 추정(조사값의 ½ 등)으로 쓰고 이유를 한 줄 적는다.
- 사람 이름·학교·직장은 블라인드한다. 대상은 팀·고객·파트너 등 **사적인 개인**이다. 출처 줄의 공공기관·언론사·공개 보고서 이름은 그대로 둔다.
- **숫자 등록부**: 완성 문서는 숫자가 많다. 헤드라인·개요·3지표·두 곳 이상 반복되는 값은 등록부에 두고(10개를 넘어도 된다), 한 번만 쓰는 값은 조사노트 출처 표(S번호)의 값을 출처와 함께 쓴다. 등록부에도 출처 표에도 없는 숫자는 쓰지 않는다.
- 출처는 기관·시점을 쓰고, 원문을 확인하지 못했으면 그렇게 표시한다.

## 9. 변환

```bash
python3 -B <설치 위치>/bizplan/scripts/build_document.py 사업계획서.md --visuals 시각자료/spec.json --pages-limit 10
```

- `--style form`(기본)이 이 서식을 입힌다.
  - 회색 상자 제목, 장 띠, □ 절, 큰 절 번호
  - 주제구 밑줄, '- 소주제'
  - 불릿 `- ·`(□○ 개조식으로 바꾸지 않는다)
  - 연노랑 머리행, 사진 격자 캡션, 개요 양식 표
  - 쪽 번호 `- n -`, 본문 11pt · 줄간격 1.3 · 양쪽 정렬
- 결과: `.docx` · `.pdf`(LibreOffice) · `_미리보기/`(쪽 PNG·모아보기) · `.hwpx`(`--hwp`면 .hwp도)
- hwpx 한계
  - 제목 상자와 장 띠는 1칸 표로 만든다.
  - 한컴오피스 화면은 이 환경에서 확인하지 못한다 — 한글에서 1회 열어 본다.
- PDF 한계: 빌드의 PDF는 LibreOffice로 그린 **미리보기**다.
  - 한국어 문단에서 숫자가 줄 끝에서 갈라질 수 있다(예: '6 / 11건'). 이 현상은 마크다운으로 고칠 수 없다.
  - 제출용 PDF는 한글·워드에서 hwpx·docx를 열어 저장한다.
