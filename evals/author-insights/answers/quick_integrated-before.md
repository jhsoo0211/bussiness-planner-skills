# RepairLog — U300 사업계획서 초안

> **작성 기준:** Q1~Q5는 모두 팀이 제공한 가상 자료다. 외부 검색과 별도 증빙 확인은 수행하지 않았다. 계산값·검토 중인 가정·향후 계획을 실적과 구분했다.  
> 모의 양식의 **문제인식·실현가능성·성장전략·팀 구성**을 적용했다. 주관기관, 배점, 지원금 규모, 공식 사업기간과 심사 방식은 **미확인**이다.

## 1. 창업 아이템 개요

**아이템명:** RepairLog  
**사업 범주:** 소형 전자제품 수리점용 업무 소프트웨어

| 항목 | 핵심 내용 |
|---|---|
| 문제 | **P1: 고장 원인 진단에 오래 걸림 → P2: 이전 수리 기록과 사진 검색에 오래 걸림** 순서 |
| 솔루션 | 수리 기록 입력·사진 첨부·과거 기록 검색으로 **P2의 기록 탐색 업무를 지원** |
| 타깃 | 수리기사 **1~3명**이 일하는 독립 수리점 |
| 차별점 후보 | 기존 파일을 가져와 장비별 기록을 모아 보는 기능. 구현 범위와 경쟁우위는 미확인 |
| 수익모델 | 점포당 **연 120만 원** 이용료 검토 중. 유료 사용·가격 수용성 검증 전 |

RepairLog는 수리점의 기록을 축적하고 다시 찾는 업무를 지원하는 서비스다. 현재는 **팀 내부 데모 단계**이며, 최우선 문제인 **P1을 직접 해결하는 진단 기능은 없다.** 따라서 초기 검증 가치는 P2에 한정하고, P1은 미해결 과제로 유지한다.

## 2. 문제인식 — Problem

### P1. 고장 원인을 진단하는 데 오래 걸림 — 최우선 문제

- 팀이 정한 **1순위 문제**다.
- 진단 소요시간과 지연 원인은 **아직 측정하지 않았다.**
- 기록 탐색이 진단 지연에 얼마나 영향을 주는지도 미확인이다. 기록 검색이 빨라진다는 이유만으로 진단시간까지 단축된다고 주장할 수 없다.
- 실제 수리기사의 작업을 관찰해 진단시간과 기록 탐색시간을 구분하여 측정할 필요가 있다.  
  *(팀 제공 자료: Q1·Q4)*

### P2. 이전 수리 기록과 사진을 찾는 데 오래 걸림 — 두 번째 문제

- 인터뷰한 **6곳 중 5곳**이 이전 기록을 찾는 데 통상 **약 20분**을 쓴다고 응답했다.
- 이는 소규모 인터뷰의 **자기보고값**이며, 현장 실측 평균이나 전체 수리점의 대표값은 아니다.
- 팀은 기록 찾기를 **5분 이하**로 줄이는 것을 시험 목표로 설정했으나 측정 결과는 없다.
- 기존 기록의 저장 방식, 사진과 장비의 연결 상태, 검색 실패 원인을 확인해 기능 설계에 반영한다.  
  *(팀 제공 자료: Q1)*

### 시장 배경과 기존 대안

- 제공 목록상 전국 동일 유형 수리점은 **2,000곳**, 현재 방문 가능한 수도권 수리점은 **400곳**이다. 이는 초기 고객 탐색 범위의 근거이지 구매 수요의 증거는 아니다.  
  *(팀 제공 자료: Q2)*
- 제공 조사에서 선두인 FixArchive의 매출은 **2023년 8억 원 → 2025년 10억 원**이다. 계산상 2년 누적 증가율은 **25%**, 연평균성장률은 **약 11.8%**다.
- 위 성장률은 **FixArchive 한 기업의 매출 성장률**이다. 다른 공급사의 2025년 매출 3억 원을 더한 **13억 원도 두 회사의 합계일 뿐 시장 전체 규모가 아니다.** 시장 성장률·점유율·전체 시장의 성장 단계는 판단할 수 없다.  
  *(팀 제공 자료: Q3 / 성장률은 제공값으로 계산)*

FixArchive는 이미 **설치 방문과 기존 파일 이전 서비스**를 함께 판매한다. 따라서 RepairLog의 파일 가져오기만으로 독창성을 주장하기 어렵다. 지원 파일 형식, 이전 정확도, 설치 소요시간, 사용 편의성과 가격을 비교해야 한다.

## 3. 실현가능성 — Solution

### 제품 범위와 개발 상태

- **수리 기록 입력 — P2 대응:** 검색할 수 있는 기록을 축적하는 기반 기능.
- **사진 첨부 — P2 대응:** 수리 기록과 관련 사진을 연결하는 기능.
- **과거 기록 검색 — P2 대응:** 필요한 이력을 다시 찾는 핵심 기능.
- **기존 파일 가져오기·장비별 모아보기 — P2 대응 후보:** 지원 형식과 구현 수준은 미확인. 별도 검증 대상으로 둔다.

제공된 개발기록으로 확인되는 수준은 **기록·검색 내부 데모**다. 사진 첨부의 개별 동작 증빙, 파일 이전 시험 결과, 현장 성능 자료는 미제공이다. **진단 기능 개발 완료나 현장 적용 완료로 표현하지 않는다.**  
*(팀 제공 자료: Q4 및 사용자 기능 설명)*

### 8주 실행계획

가용시간은 **8주 × 주당 팀 합계 16시간 = 총 128시간**이다. 아래 일정과 파일럿 규모는 **AI 생성 예시 계획이며, 실행 가능성 검증이 필요**하다. 공식 U300 사업기간을 뜻하지 않는다.

| 기간 | 팀 합계 시간 | 수행 내용 | 남길 증거 |
|---|---:|---|---|
| 1~2주 | 32시간 | 기존 인터뷰 점포에 재접촉, 파일럿 **2~3곳 모집 제안**, P1·P2 측정 기준 합의, 동의받은 비식별 파일 샘플 확보 | 참여 동의 여부, 작업 관찰 기록, 파일 형식 목록 |
| 3~4주 | 32시간 | 기록·사진·검색 동작 점검과 개선, 검색시간 기록 기능 추가. 샘플 확보 시 파일 형식 1종의 가져오기 시험 | 기능별 시험표, 오류 목록, 이전 성공·실패 기록 |
| 5~6주 | 32시간 | 협조 점포에서 검색 과제 비교, P1 진단시간 별도 관찰, 연 120만 원 가격 제시 후 반응 확인 | 검색시간·정답 여부, 진단시간 기록, 가격 수용·거절 이유 |
| 7~8주 | 32시간 | 결과 분석, 설치·지원 원가 산정, 조달 필요액 정리, 다음 개발 범위 결정. **8시간은 지연 대응 여유**로 확보 | 검증 보고서, 원가표, 후속 개발 판단 |
| **합계** | **128시간** | | |

**[이미지: 제품 개발·검증 로드맵]**

### 검증 기준

- **P2:** 실제 수리기사가 유사 난이도의 기록 탐색 과제를 기존 방식과 RepairLog로 수행하도록 하고, 과제별 소요시간과 정답 여부를 비교한다.
- **목표:** 팀이 정한 **5분 이하** 달성 여부를 기록한다. 잘못된 기록을 찾은 경우는 성공으로 세지 않는다.
- 인터뷰의 “약 20분”을 실측 대조군으로 대신 사용하지 않는다.
- **P1:** 진단시간 기준선을 확보하되, 검색 개선이 진단시간을 줄였다는 인과관계는 별도 검증한다.
- 협조 점포를 확보하지 못하면 **현장 성능·유료 검증 미완료**로 남긴다.

### 예산·자금 및 증빙 상태

- **원가:** 서버·사진 저장 비용, 방문 교통비, 설치·파일 이전 작업시간, 유지보수·고객지원 시간이 모두 **산정 예정**이다.
- **확보 방법:** 2주차까지 비용 항목과 견적 필요사항을 정리하고, 3~6주차 사용량·작업시간을 기록해 **7주차에 원가 초안**을 작성한다.
- **자금:** 확보된 재원과 조달액은 미제공이다. **8주차에 필요액·조달 후보를 정리**하며 지원금 수령을 전제하지 않는다.
- **증빙:** 내부 데모와 인터뷰 요약은 팀 설명으로 제공됐다. 현장 실측, 유료 사용, 도입 협의·계약은 없으며 수익성은 아직 계산할 수 없다.

## 4. 성장전략 — Scale-up

### 수익모델과 시장 산정

점포당 **연 120만 원**의 이용료를 검토한다. 설치·파일 이전을 이용료에 포함할지, 별도 청구할지는 원가 확인 후 결정한다.

| 구분 | 산식 | 결과 및 해석 |
|---|---|---|
| TAM 가정 | 전국 2,000곳 × 연 120만 원 | **연 24억 원**의 잠재 이용료 규모 |
| SAM 가정 | 방문 가능한 수도권 400곳 × 연 120만 원 | **연 4억 8,000만 원** |
| 첫해 SOM 목표 | 설치 지원 한도 20곳 × 연 120만 원 | **연환산 2,400만 원**의 목표 규모 |

*(팀 제공 자료: Q2 / 검토 가격을 적용한 계산)*

- TAM·SAM은 대상 점포 모두가 해당 가격으로 이용한다고 가정한 값이며 **조사된 시장 전체 매출이 아니다.**
- 첫해 **20곳**은 설치 지원 한도에 맞춘 유료 도입 목표다. SAM의 **5%**지만, 전환율이나 구매 의향으로 검증된 확보 가능 고객 수는 아니다.
- **2,400만 원**은 20곳에 만 1년 가격을 적용한 단순 연환산액이다. 도입 시점·할인·해지·지원 비용을 반영한 첫해 실제 매출이나 이익이 아니다.
- 설치 이후의 고객지원 부담까지 측정해 20곳 지원 가능성을 재점검한다.

### 초기 고객 확보

- 기존 인터뷰 **6곳에 재접촉**해 협조 의사를 확인하고, 동의 점포를 대상으로 데모와 파일럿을 제안한다.
- **접촉 → 응답 → 데모 → 파일럿 → 가격 제안 → 유료 도입** 단계별 건수와 이탈 사유를 기록한다. 현재 전환율은 없다.
- “SNS 운영” 메모는 **사용 과정 시연·파일 이전 안내·검증 결과 소개** 콘텐츠와 데모 신청 동선으로 구체화한다. 성능 홍보는 실측 확보 후 진행한다.
- 협회는 소개 메일을 보낸 잠재 접점일 뿐이다. **무응답 상태로, 확보된 판매 채널이나 협력기관이 아니다.**  
  *(팀 제공 자료: Q4 / 실행 방식은 제안)*

### 단계별 목표

- **8주:** 현장 협조 가능성, P2 검색 성능, 가격 반응, 설치·지원 부담을 확인한다.
- **첫해:** 독립 수리점 **20곳 유료 도입을 목표**로 추진하되, 검증 결과와 운영 역량에 따라 조정한다.
- **중기:** 파일 이전·설치·고객지원 절차를 표준화하고 갱신 의사와 점포당 지원시간을 확인한다.
- **장기:** 여러 점포를 가진 수리업체로 확장한다. 다점포 권한관리·기록 공유 수요와 지원 역량 확인을 선행하며, 현재 확보된 고객군으로 표현하지 않는다.

## 5. 팀 구성 — Team

- **A — 개발 담당**
  - 컴퓨터공학 학생으로 **웹 프로젝트 3개**와 RepairLog 내부 데모 개발 경험을 보유했다.
  - 향후 담당 제안: 기능 개선, 시험 기록, 파일 이전 검증, 인프라 비용 산정.
- **B — 고객 조사·디자인 담당**
  - 디자인 학생으로 **인터뷰 6건과 화면 설계**를 담당했다.
  - 향후 담당 제안: 파일럿 모집 연락, 사용성 관찰, 가격 반응 기록, 안내 자료 작성.
- **대표자 지정 여부:** 미제공.
- **역량 공백:** 두 구성원 모두 전자제품 수리 경력이 없으며, 도메인 자문과 고객지원 담당자는 **미정**이다.
- **보완 계획:** 1~2주차에 현장 수리기사의 검증 협조·자문 가능성을 타진한다. 파일럿 문의 접수는 B의 임시 역할로 제안하되, 정식 지원 책임과 대응 가능 시간을 별도로 정한다.
- **협력기관:** 확정된 기관 없음. 협회 소개 메일 발송을 제휴·도입 협의 성과로 기재하지 않는다.  
  *(팀 제공 자료: Q4·Q5 / 향후 역할 배분은 제안)*

## 6. 자체 일관성 점검

| 문제 | 대응 솔루션 요소 | 실제 판정 |
|---|---|---|
| **P1. 진단에 오래 걸림** | 현재 진단 기능 없음. 8주 계획에는 기준선 측정만 포함 | **고아 문제·미해결.** 측정 계획은 해결 기능이 아님 |
| **P2. 기록·사진 찾기에 오래 걸림** | 기록 입력·사진 연결·검색. 파일 가져오기·장비별 조회는 후보 | **기능상 대응, 효과 미검증.** 현장 시험 필요 |

- **일관성 보정:** 사용자 지정 **P1→P2 순서를 유지**했다. 제품의 현재 효익은 P2 지원으로 한정했으며, P1 해결 주장은 제외했다. 최우선 문제와 현재 제품 사이의 공백은 남아 있다.
- **차별점 판정:** 파일 이전은 경쟁사의 제공 서비스와 겹치고 모방 가능성이 있어 **고유성 근거가 약하다.** 이전 정확도·작업시간·사용 편의성 비교가 필요하다.
- **약점 보완 방향:** 수리 경험 부재는 현장 자문·관찰로, 성능·유료성 미검증은 파일럿·가격 제안으로 보완하되 확보 전에는 성과로 기재하지 않는다.
