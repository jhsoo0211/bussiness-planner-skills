# RepairLog — U300용 사업계획서 초안

> **평가용 가상 초안.** Q1~Q5의 팀 제공 자료만 사용했으며, 외부 검색이나 원본 증빙 확인은 하지 않았다. 모의 양식의 **문제인식 → 실현가능성 → 성장전략 → 팀 구성** 순서를 따른다. 실제 U300의 주관기관·배점·지원 규모·분량·심사 방식은 미확인이다. 아래 실행 일정과 역할 배분은 **제안**이다.

## 1. 창업 아이템 개요 요약

**아이템명:** RepairLog  
**사업 범주:** 소형 전자제품 수리점용 수리 기록 관리 소프트웨어

| 항목 | 핵심 내용 |
|---|---|
| 문제 | **P1: 고장 원인 진단 지연**, **P2: 이전 수리 기록·사진 검색 지연** 순서를 유지한다. 현재 제품은 P1을 해결하지 못한다. |
| 솔루션 | 수리 기록 입력·사진 첨부·과거 기록 검색. 현재 확보한 실행 자산은 **팀 내부 기록·검색 데모**다. |
| 타깃 | 수리기사 **1~3명**이 일하는 독립 수리점. 사용자는 수리기사이며, 구매 결정자는 점주로 가정하되 확인이 필요하다. |
| 차별점 후보 | 기존 파일을 가져와 장비별로 기록을 모아 보는 기능. **구현 범위·고유성·경쟁우위는 미확인**이다. |
| 비즈니스 모델 | 점포당 **연 120만 원** 이용료 검토. 첫해 **유료 도입 20곳** 목표이며, 유료 사용 검증이나 계약 실적은 없다. |

RepairLog는 과거 수리 이력에 접근하는 작업을 개선하려는 초기 제품이다. **진단 기능이나 진단시간 단축 효과를 보유한 서비스로 설명하지 않는다.**

## 2. 문제인식 — Problem

### P1. 고장 원인을 진단하는 데 오래 걸림

- **최우선 문제로 유지한다.** 다만 진단 소요시간·발생 빈도·지연 원인은 아직 측정하지 않았다.
- 기록 검색이 진단에 참고가 될 가능성은 있지만, **검색시간 감소가 진단시간 감소로 이어지는지는 미검증**이다.
- 현재 고장 원인 진단 기능은 없으므로 **미해결 문제**다. 첫 현장 조사에서 진단 과정과 시간의 기준선을 별도로 확보한다.

### P2. 이전 수리 기록과 사진을 찾는 데 오래 걸림

- 2026년 인터뷰에서 **수리점 6곳 중 5곳**이 이전 기록을 찾는 데 통상 **약 20분**이 걸린다고 응답했다. 이는 실측 평균이 아니라 **인터뷰 응답**이다. — Q1(팀 제공 자료)
- 소수 인터뷰이므로 전국 수리점 전체의 발생률이나 평균 검색시간으로 일반화하지 않는다. 사진 검색만의 부담도 별도 확인이 필요하다.
- 파일 분산, 파일명 체계, 장비 식별 방식 중 무엇이 검색 지연의 주원인인지는 미확인이다.
- **5분 이하**는 팀이 정한 시험 목표이며, 달성 결과는 없다.

### 기존 대안과 사업의 필요성

- FixArchive는 설치 방문과 기존 파일 이전 서비스를 함께 판매한다. 따라서 파일 이전 자체를 기존 공급사가 제공하지 않는 기능으로 주장할 수 없다. — Q3(팀 제공 자료)
- 초기 검증의 핵심은 **“기록을 실제로 더 빨리 찾는가, 추가 입력 부담을 감수할 만큼 유용한가, 돈을 지불할 의사가 있는가”**다.
- 경제적 손실은 미산정이다. 향후 `검색 빈도 × 실측 소요시간 × 시간당 인건비`를 확보해 추정하되, 진단 지연 비용과 중복 계산하지 않는다.

## 3. 실현가능성 — Solution

### 기능별 해결 범위와 현재 상태

- **수리 기록 입력:** P2에 필요한 검색 가능한 이력을 축적하는 기능. 입력 자체가 검색시간을 줄였다는 근거는 아직 없다.
- **사진 첨부:** P2의 시각 자료 보관·확인을 지원하는 기능. 주요 기능으로 제시됐으나, 구체적인 데모 동작 범위와 사진 검색 효과는 확인이 필요하다.
- **과거 기록 검색:** P2에 직접 대응한다. 내부 데모는 있지만 현장 검색 정확도·시간·사용 편의성은 미검증이다.
- **기존 파일 가져오기·장비별 모아보기:** P2 개선과 초기 도입을 위한 차별점 후보다. 지원 파일 형식, 장비 식별, 누락·중복 처리 및 구현 수준을 확인해야 한다.
- **고장 원인 진단:** 기능 없음. **P1은 현재 제품 범위 밖이며 미해결**이다. 이번 8주 계획에 신규 자동진단 개발을 포함하지 않는다.

### 8주 실행 계획

총 가용 자원은 **8주 × 주당 팀 합계 16시간 = 128시간**이다. 아래 시간에는 개발뿐 아니라 고객 접촉·방문 이동·시험·원가 조사·자료 정리를 모두 포함한다.

| 기간 | 팀 합계 시간 | 실행 과제와 산출물 |
|---|---:|---|
| **1~2주** | **32시간** | 기존 인터뷰 **6곳**에 재접촉하고 현장 참여 의사를 확인. P1 진단시간과 P2 검색시간의 측정 기준 설계. 데모·샘플 파일 점검, 수리 경력자 자문 섭외 시작 |
| **3~4주** | **32시간** | 기록·사진·검색 흐름 보완. 비식별 샘플의 단일 파일 형식으로 가져오기 가능성 점검. 시연 자료 준비, 서버·저장공간 등 비용 견적 확보 |
| **5~6주** | **32시간** | 참여에 동의한 **최대 2곳의 소규모 시험을 제안**. 수리기사의 검색 과제 수행과 별도 진단 과정 관찰. 설치·이전·지원 소요시간 기록 |
| **7~8주** | **32시간** | 오류 수정·재측정, 연 **120만 원** 조건에 대한 구매 반응 확인. 원가·수익성 산정, 결과와 한계 정리 및 후속 진행 판단 |
| **합계** | **128시간** | 현장 참여·목표 달성을 보장하는 일정이 아닌 실행안 |

### 검증 방법과 진행 조건

- **P2 시험:** 기존 방식과 RepairLog에서 동등한 검색 과제를 수행한다. 과제 순서에 따른 학습 영향을 줄이고, 완료시간·정확성·실패를 함께 기록한다. **5분 이하 달성 여부와 달성률**을 보고한다.
- 인터뷰의 약 20분을 그대로 실측 기준선으로 사용하지 않는다. 실제 기록량과 작업 조건을 남겨 비교한다.
- **P1 시험:** 진단 시작·종료 기준을 수리기사와 정하고 별도로 관찰한다. 검색 개선만으로 진단 개선을 입증했다고 해석하지 않는다.
- 현장 수리기사가 직접 수행하고 결과를 확인하는 검증 경로를 계획하되, **참여자나 검증 실적은 아직 확보되지 않았다.**
- 참여 점포가 없으면 내부 시험만 보고한다. 검색 목표 미달, 과도한 입력 부담, 데이터 누락이 확인되면 유료 확대를 보류하고 개선한다.

### 원가·예산·운영 위험

- **원가와 예산은 산정 예정이다.** 현금지출과 팀의 무급 투입시간을 구분한다.
- **3~4주:** 서버·사진 저장·백업 비용과 방문·자문 비용의 조건 및 견적 확보.
- **5~6주:** 점포당 설치·파일 이전·교육·고객지원 시간을 실측.
- **7~8주:** 초기 도입비와 반복 운영비를 분리해 다음을 계산한다.
  - 점포당 공헌이익 = **연 120만 원 − 점포당 연 변동비**
  - 손익분기 점포 수 = **연 고정비 ÷ 점포당 공헌이익**, 올림 처리
  - 첫해에는 설치·이전 비용을 포함하며, 공헌이익이 양수일 때만 손익분기 계산이 의미 있다.
- 손익분기점이 설치지원 한도 **20곳**을 넘으면 가격·지원 방식·비용 구조의 재검토가 필요하다.
- 파일럿 전 기록·사진의 이용 권한, 비식별 처리, 접근통제·백업·삭제 기준을 점검한다. 관련 법령·인증 적용 여부는 **확인 필요**이며, 준수 완료를 주장하지 않는다.

## 4. 성장전략 — Scale-up

### 시장 범위와 첫해 확보 목표

아래는 **2026년 대상 사업체 수에 검토 가격을 적용한 연간 잠재 이용료 계산**이다. 실제 시장 매출이나 검증된 구매 수요가 아니다. — Q2(팀 제공 자료)

| 구분 | 범위와 산식 | 계산값 | 해석 |
|---|---|---:|---|
| **TAM** | 전국 동일 유형 **2,000곳 × 연 120만 원** | **연 24억 원** | 정의한 타깃 전체의 잠재 이용료 |
| **SAM** | 현재 방문 가능한 수도권 **400곳 × 연 120만 원** | **연 4.8억 원** | 지리적으로 접근 가능한 범위 |
| **첫해 SOM 목표** | 설치지원 한도 **20곳 × 연 120만 원** | **연 2,400만 원** | 수요 검증 전의 확보 목표. SAM 점포 수의 **5%** |

- **20곳은 설치지원 한도를 반영한 목표이지 예상 계약 실적이 아니다.** 영업과 지속적인 고객지원까지 감당할 수 있는지도 추가 확인이 필요하다.
- 2,400만 원은 20곳이 모두 해당 연간 가격으로 계약할 때의 규모다. 실제 첫해 매출은 도입 시점·계약 조건에 따라 달라진다.
- 다점포 수리업체는 현재 시장 계산에 포함하지 않는다.

### 경쟁사 규모와 성장 궤적

- 제공 자료 내 선두인 **FixArchive:** 2023년 **8억 원 → 2025년 10억 원**. 계산상 **2년간 25% 증가**, 연평균 증가율은 **약 11.8%**다.
- 다른 공급사 한 곳은 2025년 **3억 원**이며, 이전 연도 자료가 없어 성장률을 계산할 수 없다. — Q3(팀 제공 자료)
- 두 공급사의 매출 합계는 **시장 전체 매출이 아니다.** FixArchive의 성장률을 시장 성장률로 일반화하거나 시장점유율을 산정하지 않는다.
- FixArchive 매출에는 설치·파일 이전 서비스가 함께 관련돼 있어 RepairLog의 이용료 기반 잠재시장과 직접 비교하기 어렵다.
- **시사점·가설:** 초기 고객은 소프트웨어뿐 아니라 기존 기록 이전과 설치 지원을 중요하게 볼 수 있다. 이 가설을 고객 인터뷰와 지원시간 측정으로 확인한다.

### 초기 시장진입 행동

- 현재 실행 상태는 **협회 소개 메일 발송·무응답**, 홍보 계획은 **‘SNS 운영’ 메모 수준**이다. 도입 협의나 계약으로 표현하지 않는다. — Q4(팀 제공 자료)
- **1~2주:** B가 기존 인터뷰 6곳에 재접촉해 실제 검색 사례와 시연 참여 의사를 확인한다.
- **3~6주:** A가 준비한 데모로 기록 찾기 과정을 시연하고, 동의 점포에서 현장 시험을 진행한다.
- **7~8주:** 시험 결과와 지원 범위를 설명한 뒤 연 120만 원 조건을 제안한다. 관심 표현·구매의향·계약을 구분해 기록한다.
- SNS는 검증 후 비식별 시연 자료를 공유하는 보조 채널로 구체화한다. 유료 광고 예산이나 고객획득 효과는 아직 산정하지 않는다.

연간 영업 계획은 다음 구조로 검증한다.

**유료 도입 수 = 접촉 점포 수 × 시연 참여율 × 시험 참여율 × 유료 전환율**, 단 현재 설치지원 한도는 **20곳**이다. 각 전환율은 미확인이므로 임의로 채우지 않는다.

### 목표·자금·확장 방향

- **단기·8주:** 현장 기준선, 검색 성능, 가격 반응, 설치·지원 원가 확보.
- **중기·첫해:** 검증 결과와 운영 여건을 확인하면서 유료 도입 **20곳**을 추진. 근거가 부족하면 목표와 실행 방식을 재검토한다.
- **장기:** 여러 점포를 가진 수리업체로 확장. 점포 간 기록 공유·권한 관리 수요를 별도로 검증한 뒤 개발 범위를 결정한다.
- **자금:** 확보 내역과 조달 조건이 미제공 상태다. 지원금·투자금을 확보 자금으로 반영하지 않는다. 견적을 바탕으로 필요한 현금과 재원 후보를 정리하고, 비용이 발생하는 확대는 재원 확인 후 진행한다.

— Q5(팀 제공 자료)

- **대표자:** 미제공. A를 임의로 대표자로 기재하지 않으며, 1주차에 대외 의사결정 역할을 정하는 안을 제안한다.
- **도메인 공백:** 팀에 전자제품 수리 경력자가 없다. B가 1~2주에 현장 수리 경력자를 섭외하고 4주까지 참여 가능 범위와 조건을 확인한다. 미확보 시 전문 진단 관련 주장이나 개발 확대를 보류한다.
- **고객지원 공백:** 현재 담당자가 정해지지 않았다. 파일럿 전 **B의 문의 접수·교육, A의 기술 대응**으로 임시 분담하는 안을 제안하고 실제 소요시간을 측정한다.
- **협력기관:** 가상 수리점협회에는 소개 메일만 발송했으며 답장이 없다. **협력 협의·MOU·계약·자문 확보 상태가 아니다.** 인터뷰 참여 점포도 협력사나 유료 고객으로 간주하지 않는다.

## 6. 자체 일관성 점검

| 문제 — 우선순위 유지 | 대응 솔루션 요소 | 실제 판정 |
|---|---|---|
| **P1. 고장 원인 진단 지연** | 직접 대응 기능 없음. 과거 기록은 참고 자료가 될 가능성만 있음 | **미해결·현재 제품 범위 밖.** 진단시간과 원인부터 별도 확인해야 하며, 검색 개선으로 해결됐다고 볼 수 없음 |
| **P2. 이전 기록·사진 검색 지연** | 기록 입력·사진 첨부·과거 기록 검색. 파일 가져오기·장비별 모아보기는 후보 | **대응 설계는 있으나 효과는 추가 검증 필요.** 내부 데모만 있으며 **5분 이하**는 시험 목표 |

- **차별점 판정:** 고유성과 모방 난이도를 입증할 근거가 부족하다. 기존 공급사의 파일 이전 서비스와 구분되는 장비별 정리 방식·검색 편의·지원 부담을 비교해야 한다.
- **약점 보완 방향:** 현장 수리기사의 검증 참여, 유료 조건에 대한 실제 반응, 설치·고객지원 비용을 확보한다. **P1 미해결 상태는 이 보완만으로 자동 해소되지 않는다.**

### 보강 제안 — 향후 확보할 자료

추가 질문 없이, 다음 보강 순서만 남긴다.

1. **진단·검색 현장 로그와 인터뷰 원자료 → 문제인식·실현가능성:** 문제의 크기와 개선 효과를 구분해 설명하는 근거. **1~6주 확보 추진.**
2. **데모 영상·시험 기록·파일 가져오기 점검 결과 → 실현가능성:** 기능 설명을 실제 동작 증거로 보강. **2~8주 정리.**
3. **비용 견적·지원시간표·가격 제안 응답 → 성장전략:** 목표 매출을 수익성과 구매 가능성에 연결. **3~8주 확보 추진.**
4. **자문 참여 조건·고객지원 역할 합의 → 팀 구성:** 핵심 공백을 누가 책임질지 명확화. **파일럿 전 확인.**
5. **실제 공고·배점표·전체 제출 양식 → 전 항목:** 정식 제출로 전환할 때 항목·분량·지원 조건에 맞춰 재배치.
