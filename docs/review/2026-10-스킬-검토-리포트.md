# bizplan 스킬 검토 리포트 (v0.4.0 기준, 2026-10)

> 관점: 정부지원사업 사업계획서 컨설팅 + 문서 산출(한글·워드) 실무.
> 기능 라우팅보다 **"실제로 제출 가능한 문서가 나오는가"**와 **"재무·비즈니스 내용이 심사 기준을 채우는가"**에 초점을 뒀다.

## 요약

1. **내용 설계는 수준이 높다.** 문제-솔루션 1:1 대응, 출처·추정 구분, "산정 예정" 폴백, TAM/SAM/SOM 산정, 심사위원 인사이트의 [확인]/[의견]/[추론] 구분은 실전 컨설팅 수준이다.
2. **문서 산출은 "초안 열람용"에 머문다.** .docx 변환본은 Letter 용지·테두리 없는 표·영문 제목 스타일이고, 한글(HWP/HWPX)은 읽기·쓰기 모두 미지원이다.
3. **재무 파트는 "채점은 하는데 만들지는 않는" 불일치가 있다.** 검토(review)는 재무추정·BEP·검산을 감점 요인으로 보지만, 작성 스킬에는 재무추정·자금조달 표를 만드는 지침이 없다.

## 2. 문서 산출 품질 (형식)

| 경로 | 현재 지침 | 실측 결과 | 판정 |
|------|-----------|-----------|------|
| 채팅 / .md | 섹션별 누적 | 정상 | ○ |
| .docx (pandoc 기본) | `pandoc 사업계획서.md -o 사업계획서.docx` | **Letter 용지(612×792pt)**, **표 테두리 없음**, 좁은 열에서 글자 단위 줄바꿈("polypharm / acy"), 영문 테마 제목 스타일, 언어 태그 `en-US`, 상대경로 이미지 3건 누락(`--resource-path` 미지정) | △ 열람용 |
| .docx (python-docx 폴백) | 제목·굵게·표 변환 | 서식 기준(용지·글꼴·표 테두리)이 지침에 없음 → 매번 결과가 달라짐 | △ |
| HWP / HWPX 읽기 | "읽을 수 없으면 목차를 붙여넣어 달라" | `python-hwpx`로 `.hwpx`·`.hwp` 모두 열기 가능 확인 → 양식 목차·표 자동 추출 여지 | ✕ (미활용) |
| HWP / HWPX 쓰기 | 없음 ("최종 제출본은 HWP — 이관은 사용자 몫") | 제목·□○- 개조식·3×3 표 생성 → `validate()` 이슈 0건 → `.hwp` 저장 후 재열기 텍스트 일치 | ✕ (미지원, 기술적으로 가능) |

> **확인 필요**: 생성한 `.hwpx`가 한컴오피스 한글에서 의도대로 보이는지(글꼴·표 테두리·줄간격)는 이 환경에서 렌더할 수 없다. 실제 한글 프로그램에서 1회 열람 확인이 구현 전 필수다.

**시사점**
- 제출 양식이 한글인 이상, md → docx → (사용자가 한글에서 열기) 경로는 표·글꼴이 깨지는 지점이 두 번 생긴다.
- 최소 조치: `.docx`에 **A4·한국어 글꼴·테두리 표**를 지정한 기준 서식(reference.docx) 적용 + `--resource-path` 추가.
- 근본 조치: **HWPX 직접 생성**, 더 나아가 **공고 양식(.hwpx) 칸 채우기**.

## 3. 재무·비즈니스 내용 품질

### 잘 된 점
- 원가 미산정 시 "산정 예정(견적처·시점)" 폴백 — 빈칸보다 낫다는 원칙이 명확하다.
- TAM·SAM은 "시장 지출", SOM은 "자사 매출 목표"로 성격을 구분하고 반복매출/일시매출을 분리한다.
- 회계사·세무사 심사위원의 검산 성향을 인지하고 "숫자 모순" 감점 사례를 축적했다.

### 보완이 필요한 점

| # | 항목 | 현재 | 문제 | 제안 |
|---|------|------|------|------|
| F1 | **예산 비목** | `bizplan-solution` B표: 인건비 / 외주·용역 / 장비·SW / 마케팅 / 운영비 | 정부지원사업 집행 비목 체계와 이름·구분이 다르다. 그대로 옮기면 양식 표와 맞지 않는다 | 사업별 비목 프로필(예: 재료비·외주용역비·기계장치·특허권등무형자산취득비·인건비·지급수수료·여비·교육훈련비·광고선전비·창업활동비 등)을 두고 공고·지침 연도로 확인 — **기준 연도 합의 필요** |
| F2 | **재무추정** | 작성 스킬에 연차별 매출·원가·손익·BEP 표 없음 | `bizplan-review`는 "재무 추정 5점", "하부 가정 분해", "BEP 미제시 감점"으로 채점 → **채점-생산 불일치** | `bizplan-growth`에 "매출 추정 = 고객 수 × 단가 × 전환율" 분해표 + 3~5개년 손익 요약 + BEP 추가 |
| F3 | **자금 조달 계획** | 정부지원금만 다룸 | 자기부담(현금·현물)·투자유치·융자를 구분하는 사업에 대응 못 함. 확보/목표 구분 원칙(case-insights)도 표로 강제되지 않음 | 조달원 × 확보 상태(확보/협의/목표) 표 |
| F4 | **검산** | 모델이 눈으로 검산 | 합계·비율 100%·단위(원/만원/억) 오류는 감점 1순위인데 자동 확인 수단 없음 | 예산·재무표를 수식이 살아 있는 `.xlsx`로 함께 산출하거나, 검산 스크립트 추가 |
| F5 | **기본값** | "예창패 1단계 2천만 + 2단계 4천만, 8개월" | 연도별 공고가 바뀌는 수치가 여러 스킬에 박혀 있음 | 기본값을 `common-rules.md` 한 곳으로 모으고 "기준 연도"를 명기 — **최신 공고 확인 필요** |

## 4. 한국 사업계획서 특화 점검

- PSST 순서 고정, 배점표 매핑 우선, 제출 양식 핏(양식 > 스킬 기본 구조), 양식 안내 문구 삭제 표시.
- 대표자 직접 발표·이력 진위 질의 대비, U300 학생 트랙 항목별 폴백.

### 보완 후보 (상의 필요)

| # | 항목 | 현재 | 쟁점 |
|---|------|------|------|
| K1 | **개조식 표기 체계** | 마크다운 불릿 + **굵게** 위주 | 한국 공공 문서의 `□ → ○ → - → ·` 계층과 "~함·~임·~음" 명사형 종결을 표준으로 정할지. Re:Shell 예시는 `□`를 쓰고 PILLY 예시는 쓰지 않아 예시끼리도 다르다 |

## 5. 신규 기능 설계안 (구현 전 합의용)

### 5-1. 큰틀 보기 (가칭 `bizplan-outline`)

목적: 본문을 쓰기 전에 **제목 → 중제목 → 소제목 → 한두 줄 요약**까지 한눈에 보고 바로 작성에 들어간다.

산출 형태(안):

| 대제목 | 중제목 | 소제목 | 한두 줄 요약 | 근거·증빙 슬롯 | 권장 분량 |
|--------|--------|--------|--------------|----------------|-----------|
| 1. 문제인식 | 1-1. 배경 및 필요성 | □ 독거 만성질환자의 복약 공백 | 독거노인 약 235만 명, 앱 기반 복약알림은 이들에게 닿지 않음 | 통계청 고령자통계 / [증빙] 보호자 인터뷰 | 1쪽 |
| | | □ 기존 솔루션의 한계 | 앱은 폰 의존, 약통은 복용 감지 불가 | 경쟁 비교표 | 0.5쪽 |
| 2. 실현가능성 | 2-1. 현황(준비 정도) | … | … | … | … |

- 양식 파일이 있으면 양식 목차를 그대로 대·중제목으로 사용, 없으면 PSST 기본 목차.
- 배점표가 있으면 "권장 분량"을 배점 비율로 자동 배분.
- 요약 1~2줄은 이후 각 섹션 스킬의 입력으로 그대로 넘긴다(작성 일관성 확보).

### 5-2. 한글(HWPX) 지원

| 단계 | 기능 | 난이도 | 비고 |
|------|------|--------|------|
| ① 읽기 | 양식 `.hwp`·`.hwpx`에서 목차·표·안내 문구 추출 → "제출 양식 핏"에 자동 투입 | 낮음 | 현재 "붙여넣기 요청" 폴백 대체 |
| ② 새 문서 생성 | 누적 `.md` → 공문서 서식(A4·□○- 계층·테두리 표) `.hwpx` | 중간 | 한컴에서 렌더 확인 필요 |
| ③ 양식 채우기 | 공고 양식 `.hwpx`의 칸·표를 찾아 본문 삽입, 안내 문구 제거 | 높음 | 제출 품질에 가장 가까움. 양식마다 구조가 달라 검수 절차 필수 |

의존성: `python-hwpx`(PyPI, Apache-2.0). 설치가 불가능한 환경은 `.docx` 폴백.

### 5-3. 수상작·우수 사례 반영

- 원문을 저장소에 넣을지, **패턴(목차 구조·문장 공식·시각자료 문법)만 추출**해 넣을지 결정 필요 — 공개 저장소라면 후자가 안전하다.
- 저장 위치 후보: 검토 기준 → `bizplan-review/references/case-insights.md`, 작성 공식 → 신규 `references/award-patterns.md`(분야 × 사업 × 섹션).
- `bizplan-analyze`의 "인사이트 축적" 루프를 그대로 활용.

## 6. 상의 항목 목록

상세 질문과 권장안은 대화로 진행한다. 결정되면 이 문서 하단에 결정 사항을 기록한다.

1. 기본 기준 연도·사업(예창패 2026 등)과 예산 비목 체계 (F1·F5)
2. 재무추정·자금조달 표 추가 위치와 `.xlsx` 동시 산출 여부 (F2~F4)
3. 개조식 표기 체계 표준화 (K1)
4. 블라인드 마스킹 방식 (K2)
5. 개요(요약) 1쪽 양식 정합 (K3)
6. 지원사업 프로필 확대 범위 (K4·K5)
7. 큰틀 보기: 별도 스킬 vs 라우터 첫 단계 (5-1)
8. 한글 지원 우선순위: 읽기 → 생성 → 양식 채우기 순서 여부 (5-2)
9. 수상작 자료: 원문 보관 여부·익명화 수준 (5-3)
