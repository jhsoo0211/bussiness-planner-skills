# 디자인 분류·호스트 적용 검토

검토 기준: PR #8 최초 구현(`7ebebbfb2fffb93d1f751d009c1b436afd7f31ad`). 기존 PSST 논리·관계 판별·구성안 매핑을 보존하면서, Claude Code와 Codex의 진입 방식 차이가 파싱·디자인 적용을 끊는지 점검했다.

| 발견 | 영향 | 수정 |
|---|---|---|
| 디자인 도우미가 미리 만든 단위 JSON을 필수로 요구 | 원문만 받은 직접 호출에서 자동 분류가 끊김 | `--doc` 입력으로 기존 파서만 호출, 문맥은 대화에서 확인한 CLI 인자로 전달 |
| 루트·시각자료·발표 지침이 분류 실행을 공통 필수 단계로 연결하지 않음 | 호스트가 스킬을 읽어도 다른 명령·JSON 준비를 사용자에게 넘길 수 있음 | 공통 자동 준비 계약과 각 진입점 연결. 실행 도구가 없을 때는 대화 안에서 같은 기준 적용 |
| 기존 덱에도 새 구성안 설계를 요구하고, 테마를 사용자에게 고르게 하는 지침이 남음 | 디자인만 바꾸는 요청에서 기존 내용·순서가 재설계되거나 작업이 중단됨 | 기존 덱·단위 재사용, 새 설계는 신규 제작에만 적용, 디자인 선호 충돌 때만 질문 |
| 시각자료 제작 다음에 디자인 분류 단계가 위치 | 디자인 선택보다 제작이 먼저 일어날 수 있음 | 분류 → 제작 순서로 작업 절차 정리 |
| 조사 출처·식별자가 일반 안내·기본 출력에 반복 노출 | 사용자에게 불필요한 내부 작업 정보가 전달됨 | 기본 설명은 적용 디자인 중심, 출처는 내부 JSON에 유지, 상세 출력은 `--details` |
| 기존 출력 파일이 있으면 재실행 거부 | 같은 산출물 갱신 대신 새 파일을 만들게 됨 | 디자인 출력은 갱신하고 원문·파싱·원본 테마와의 경로 충돌은 차단 |
| 관계 미확정 코드 `—`를 보류하지 않음 | 관계가 미정인 목록에도 확정된 표현처럼 추천할 수 있음 | `?`·빈 코드와 함께 추천 보류 |

검증은 설치 경로·결정적 코드 실행과 실제 모델의 스킬 선택을 구분한다. 회귀 검사는 원문/기존 단위 경로, CLI 문맥 전달, 반복 실행, 원문·테마 보존, 기본 출력, Claude 로컬·Codex·Claude 플러그인 구조의 동일 결과를 확인한다. 실제 Claude·Codex 모델 세션에서의 자연어 선택·지침 이행은 이 검사로 검증했다고 주장하지 않는다. 해당 사례는 `evals/trigger-evals.json` 42–45에 추가했다.

`suggest_patterns.py`, `info-patterns.md`, 발표 흐름 설계 기준, PPT·HTML 렌더러의 관계·데이터 처리 코드는 수정하지 않았다. 자동 준비 도우미와 실행 지침만 변경했다. 원본 디자인 파일·이미지·썸네일은 추가하지 않았다.
