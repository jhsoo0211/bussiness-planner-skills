## 2. 톤앤매너

- **차분한 한국 비즈니스 톤.** 화려한 효과보다 "정리되는 쾌감"이 핵심 감정이다 — 흩어진 것이 제자리에 맞물리는 모션.
- 플랫·미니멀 벡터, 넓은 여백. 실사 인물·악수 사진·달러 기호·만화 마스코트 사용 안 함.
- 정부·기관 로고, 실제 공고문 이미지는 쓰지 않는다(기관 사칭·공식 제휴 오해 방지). "합격 보장" 같은 표현도 쓰지 않는다.

| 요소 | 값 |
|------|----|
| 기본색 | 네이비 `#1F3A5F` |
| 강조색 | 오렌지 `#F28C28` (신규 기능·핵심 수치에만) |
| 배경 | 오프화이트 `#F7F8FA` |
| 보조 | 그레이 `#8A94A6`, 연네이비 `#DCE4EE` |
| 글꼴 | Pretendard (대체: Noto Sans KR) — 제목 Bold, 본문 Medium |
| 모션 | ease-out 중심, 컷당 1~2개 동작, 0.4~0.6초 전환 |

## 4. S4 "어디를 돕나" 상세 — 6단계 여정

각 노드 약 3초. 노드 위 칩 = 해당 스킬, 아래 미니 화면 = 실제 산출물 모양.

| # | 단계 | 스킬 칩 | 미니 화면 (가시화 포인트) |
|---|------|---------|---------------------------|
| 1 | 아이디어 구체화 | `bizplan-item` `bizplan-quick` | 질문 카드 5장(업종·타겟·핵심기능·차별점·약점)이 한 장의 기획 요약으로 합쳐짐 |
| 2 | 큰틀 잡기 **NEW** | `bizplan-outline`(예정) | 제목 → 중제목 → 소제목 → 한두 줄 요약 트리가 위에서 아래로 펼쳐짐 |
| 3 | PSST 작성 | `problem` `research` `solution` `growth` `team` | P·S·S·T 4블록. 문제 3개와 솔루션 3개 사이에 **1:1 연결선**이 그려짐 |
| 4 | 시각자료 | `bizplan-visual` | TAM·SAM·SOM 동심원이 바깥부터 차오르고, 포지셔닝맵에 점이 찍힘 |
| 5 | 심사위원 검토 | `bizplan-review` `bizplan-analyze` | 100점 채점표에 O·△·X가 찍히고 "필수 수정 2건" 태그 등장 |
| 6 | 발표 준비 | `bizplan-pitch` `bizplan-slides` | 16:9 슬라이드 썸네일 + 예상 질문 카드가 넘겨짐 |

> 수출바우처(`bizplan-export`)는 6단계와 별도 갈래 — 숏폼에서는 생략, 메인에서는 S4 끝에 "수출바우처 전용 모드" 칩 1개로만 노출.

## 5. S6 설치 화면 — 명령어 (화면에 그대로 표시)

> 명령어는 README 기준이다. 저장소 이름은 `bussiness-planner-skills`(s 두 번), 마켓플레이스 이름은 `business-planner-skills`(s 한 번)로 **철자가 다르다** — 화면 텍스트 오타 검수 1순위.

**왼쪽 — Claude Code**
```text
/plugin marketplace add jhsoo0211/bussiness-planner-skills
/plugin install bizplan@business-planner-skills
```
사용 예: `/bizplan 예비창업패키지 사업계획서 쓰고 싶어`

**오른쪽 — Codex**
```bash
git clone https://github.com/jhsoo0211/bussiness-planner-skills.git
cd bussiness-planner-skills
python scripts/install_skills.py --agent codex
```
사용 예: `$bizplan 예비창업패키지 사업계획서 쓰고 싶어`

> 화면에는 강조할 마지막 한 줄(`/plugin install …`, `python scripts/install_skills.py --agent codex`)만 크게, 나머지는 작게 처리한다.

## 7. 사운드

- BGM: 차분한 코퍼릿 로파이, 약 100 BPM, 피아노 + 부드러운 신스, 보컬 없음.
- 효과음: 카드 정렬 "틱", 노드 점등 "핑"(아주 작게), 설치 완료 체크 "딩" 1회.
- 내레이션: 30대 차분한 톤, 약 230~260음절. 자막은 내레이션과 별도로 **상시 노출**.

## 8. 제작 방식 — 3가지 선택지

| 방식 | 장점 | 단점 | 추천 용도 |
|------|------|------|-----------|
| **A. 코드 기반** (HTML + GSAP, 또는 Remotion) | 한글 텍스트·명령어가 100% 정확, 수정·재렌더 쉬움, Claude/Codex로 생성 가능 | 실사·질감 표현 약함 | **본편 전체** (권장) |
| B. 툴 기반 (After Effects, Figma + Jitter 등) | 디자이너가 세밀하게 조정 | 수작업 시간 | 디자이너가 있을 때 |
| C. AI 영상 생성 (Runway·Kling·Veo 등) | 분위기·전환 컷을 빠르게 | **한글 글자를 자주 깨뜨림**, 명령어 표시 불가 | S1·S2 배경 컷 보조 — 텍스트는 후합성 |

권장 조합: **A로 본편 + C로 S1·S2 배경 질감만 보조.** 프롬프트는 `02-프롬프트.md`에 A·C 모두 준비했다.
